Log چیست؟

Logها اطلاعاتی هستند که سیستم‌عامل و سرویس‌ها درباره اتفاقاتی که در سیستم رخ می‌دهد ثبت می‌کنند.

در محیط DevOps، Logها یکی از مهم‌ترین منابع برای پیدا کردن علت خطا هستند.

برای مثال اگر یک سرویس بالا نمی‌آید، به جای حدس زدن می‌توانیم ابتدا Log آن سرویس را بررسی کنیم.

💡 قانون مهم Troubleshooting:

قبل از تغییر دادن تنظیمات، اول ببین سیستم چه خطایی گزارش کرده است.

journalctl

در سیستم‌هایی که از systemd استفاده می‌کنند، دستور journalctl یکی از ابزارهای اصلی مشاهده Log است. 

journalctl

برای مشاهده آخرین Logها: 

journalctl -n 50

برای مشاهده Log یک Service: 

journalctl -u nginx

یا: 

journalctl -u ssh

برای مشاهده Logهای جدید به صورت زنده: 

journalctl -f

Syslog

در بسیاری از سیستم‌های Linux فایل‌هایی مانند: 

/var/log/syslog

برای ثبت رویدادهای سیستم استفاده می‌شوند.

برای مشاهده: 

sudo tail -f /var/log/syslog

Authentication Logs

یکی از Logهای مهم در Ubuntu: 

/var/log/auth.log

این Log می‌تواند اطلاعاتی درباره Authentication و فعالیت‌های مرتبط با Login ارائه دهد. 

sudo tail -f /var/log/auth.log

برای پیدا کردن تلاش‌های ناموفق Login: 

sudo grep "Failed password" /var/log/auth.log

بررسی وضعیت Service

اگر یک سرویس کار نمی‌کند، اولین مرحله بررسی وضعیت آن است. 

systemctl status nginx

اگر Service اجرا نشده باشد: 

sudo systemctl start nginx

برای Restart: 

sudo systemctl restart nginx

بعد از Restart دوباره Log را بررسی کن.

جستجو در Logها با grep

Logها ممکن است بسیار بزرگ باشند. بنابراین باید بتوانیم داخل آن‌ها جستجو کنیم. 

grep "error" /var/log/syslog

جستجوی بدون حساسیت به حروف: 

grep -i "error" /var/log/syslog

نمایش شماره خط: 

grep -n "error" /var/log/syslog

tail و head

برای مشاهده انتهای فایل: 

tail /var/log/syslog

مشاهده 50 خط آخر: 

tail -n 50 /var/log/syslog

برای مشاهده ابتدای فایل: 

head /var/log/syslog

روش اصولی Troubleshooting

وقتی با یک مشکل مواجه می‌شویم، بهتر است به جای اجرای تصادفی دستورات یک Workflow مشخص داشته باشیم.

مرحله ۱ — مشکل را دقیق تعریف کن

مثلاً: Nginx اجرا نمی‌شود.

مرحله ۲ — وضعیت سرویس را بررسی کن 

systemctl status nginx

مرحله ۳ — Log را بررسی کن 

journalctl -u nginx -n 100

مرحله ۴ — منابع سیستم را بررسی کن 

df -h
free -h
uptime

مرحله ۵ — تغییرات اخیر را بررسی کن

بررسی کن آیا قبل از ایجاد مشکل Configuration، Package یا Service جدیدی تغییر کرده است.

مرحله ۶ — بعد از اصلاح دوباره تست کن

بعد از تغییر، Service را تست و Logها را دوباره بررسی کن.

مثال واقعی

فرض کنیم Nginx بالا نمی‌آید.

ابتدا: 

sudo systemctl status nginx

سپس: 

sudo journalctl -u nginx -n 100

اگر خطایی مربوط به Port دیدیم، بررسی می‌کنیم چه Process دیگری از آن Port استفاده می‌کند. 

sudo ss -tulpn

🧪 تمرین عملی

روی Ubuntu خود این دستورات را اجرا کن: 

journalctl -n 50
journalctl -b
sudo systemctl status ssh
sudo journalctl -u ssh -n 30
df -h
free -h
uptime
ss -tulpn

📌 Cheat Sheet

دستور کاربرد
journalctl مشاهده Journal
journalctl -u nginx Log سرویس
journalctl -f مشاهده Live Log
tail -f file مشاهده زنده فایل
grep "error" file جستجوی Error
systemctl status service وضعیت Service
ss -tulpn مشاهده Portها
