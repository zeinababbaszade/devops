Log چیست؟

Log یا گزارش رویداد، اطلاعاتی است که سیستم‌عامل و Applicationها درباره اتفاقاتی که در سیستم رخ می‌دهد ثبت می‌کنند.

وقتی یک سرویس Crash می‌کند، یک User Login می‌شود، یک اتصال شبکه برقرار می‌شود یا یک Application خطایی ایجاد می‌کند، ممکن است اطلاعات مربوط به آن در Log ثبت شود.

💡 یکی از مهم‌ترین مهارت‌های DevOps این است که به جای حدس زدن، از Logها برای پیدا کردن علت واقعی مشکل استفاده کند.

journalctl

در سیستم‌هایی که از systemd استفاده می‌کنند، ابزار journalctl یکی از مهم‌ترین ابزارهای مشاهده Log است.

Terminal
journalctl

برای دیدن Logهای مربوط به یک Service:

Terminal
journalctl -u ssh

برای دیدن Logهای جدیدتر:

Terminal
journalctl -u ssh -n 50

برای مشاهده Logها به صورت زنده:

Terminal
journalctl -u ssh -f

بررسی سرویس‌ها

قبل از بررسی Log یک سرویس، بهتر است وضعیت خود Service را بررسی کنیم.

Terminal
systemctl status ssh

اگر سرویس Failed شده باشد، معمولاً در خروجی Status اطلاعات اولیه‌ای درباره مشکل می‌بینیم.

دستور tail

برای مشاهده انتهای یک فایل Log از tail استفاده می‌کنیم.

Terminal
tail /var/log/syslog

برای مشاهده زنده تغییرات فایل:

Terminal
tail -f /var/log/syslog

جستجو با grep

وقتی یک فایل Log بزرگ است، پیدا کردن خط موردنظر با نگاه کردن به کل فایل سخت است. در اینجا grep بسیار کاربردی می‌شود.

Terminal
grep "error" /var/log/syslog

برای جستجوی بدون حساسیت به حروف بزرگ و کوچک:

Terminal
grep -i "error" /var/log/syslog

ترکیب ابزارها بسیار قدرتمند است:

Terminal
journalctl -u ssh | grep -i failed

مسیرهای مهم Log

در Ubuntu و بسیاری از Distributionهای Linux، Directory مهم Log این مسیر است:

Directory
/var/log

برخی فایل‌ها و مسیرهای رایج:

  • /var/log/syslog برای برخی رویدادهای عمومی سیستم.
  • /var/log/auth.log برای رویدادهای مرتبط با Authentication در سیستم‌هایی که این فایل فعال است.
  • Logهای سرویس‌ها که ممکن است بسته به Application و تنظیمات در مسیرهای مختلف قرار داشته باشند.

روش Troubleshooting

برای Troubleshooting بهتر است مرحله به مرحله جلو برویم و از حدس زدن خودداری کنیم.

  1. مشکل را دقیق تعریف کن.
  2. وضعیت Service را بررسی کن.
  3. Logهای مرتبط با همان Service را بررسی کن.
  4. زمان رخ دادن خطا را مشخص کن.
  5. خطاهای مهم را با grep پیدا کن.
  6. تغییرات اخیر سیستم را بررسی کن.
  7. بعد از اصلاح مشکل، دوباره Service را تست کن.
💡 همیشه سعی کن ابتدا Scope مشکل را مشخص کنی: مشکل فقط برای یک Service است یا کل سیستم؟ این کار مسیر Troubleshooting را بسیار کوتاه‌تر می‌کند.

تمرین عملی: Troubleshooting Lab

🧪 تمرین

ابتدا وضعیت SSH را بررسی کن:

Terminal
systemctl status ssh

سپس 50 Log آخر SSH را ببین:

Terminal
journalctl -u ssh -n 50

حالا Logها را با grep فیلتر کن:

Terminal
journalctl -u ssh | grep -i failed

در نهایت Directory مربوط به Logها را بررسی کن:

Terminal
sudo du -h --max-depth=1 /var/log

Logs Cheat Sheet

Command کاربرد
journalctl مشاهده Journal
journalctl -u SERVICE Log یک Service
journalctl -f مشاهده زنده Logها
systemctl status SERVICE بررسی وضعیت Service
tail -f FILE مشاهده زنده فایل Log
grep "text" FILE جستجو داخل Log
/var/log مسیر مهم Logها

چیزی که از این مرحله یاد گرفتم

  • Log یکی از مهم‌ترین منابع برای Troubleshooting است.
  • با journalctl می‌توانم Journal سیستم را بررسی کنم.
  • با systemctl status وضعیت Service را می‌بینم.
  • با tail انتهای فایل‌های Log را بررسی می‌کنم.
  • با grep می‌توانم خطاهای خاص را پیدا کنم.
  • قبل از تغییر سیستم باید علت مشکل را از شواهد موجود پیدا کنم.
