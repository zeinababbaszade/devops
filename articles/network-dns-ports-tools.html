DNS چیست؟

DNS یا Domain Name System سیستمی است که Nameهایی مانند:

Domain 
example.com

را به IP Address مربوط می‌کند.

برای انسان به خاطر سپردن Domain Name راحت‌تر از IP است. ولی در نهایت سیستم برای برقراری ارتباط شبکه‌ای به IP نیاز دارد.

DNS Records

DNS فقط برای یک نوع اطلاعات استفاده نمی‌شود. Recordهای مختلفی وجود دارند که هرکدام کاربرد خاصی دارند.

Record کاربرد
A تبدیل Domain به IPv4
AAAA تبدیل Domain به IPv6
CNAME Alias برای یک Domain دیگر
MX مشخص کردن Mail Server
TXT ذخیره اطلاعات متنی مانند برخی تنظیمات Verification

بررسی DNS با dig

برای بررسی DNS می‌توانیم از dig استفاده کنیم.

Ubuntu 
dig example.com

برای درخواست مستقیم یک نوع Record:

A Record 
dig example.com A

یا:

MX Record 
dig example.com MX

اگر dig روی Ubuntu نصب نباشد، معمولاً می‌توان بسته مربوط به ابزارهای DNS را نصب کرد.

Ubuntu 
sudo apt update
sudo apt install dnsutils

Port چیست؟

IP Address مشخص می‌کند با کدام Host صحبت می‌کنیم، اما در یک Host ممکن است چندین سرویس مختلف همزمان در حال اجرا باشند.

Port کمک می‌کند سیستم مشخص کند Packet یا Connection مربوط به کدام سرویس است.

مثلاً:

Port Service رایج
22 SSH
53 DNS
80 HTTP
443 HTTPS
5432 PostgreSQL
3306 MySQL
💡 Port متعلق به یک سرویس یا Endpoint ارتباطی است، نه اینکه ذاتاً و همیشه متعلق به یک Application خاص باشد. یک سرویس می‌تواند روی Port دیگری نیز پیکربندی شود.

TCP چیست؟

TCP یک Protocol اتصال‌گراست. قبل از انتقال داده، طرفین یک Connection ایجاد می‌کنند.

TCP برای Applicationهایی مناسب است که تحویل قابل اعتماد و مرتب داده اهمیت دارد.

HTTP، HTTPS و SSH نمونه‌هایی از Protocolهایی هستند که معمولاً روی TCP اجرا می‌شوند.

UDP چیست؟

UDP برخلاف TCP Connection-oriented نیست و Overhead کمتری دارد.

UDP در سناریوهایی که سرعت و سادگی اهمیت دارد یا Application خودش مدیریت Reliability را انجام می‌دهد، بسیار استفاده می‌شود. DNS یکی از نمونه‌های شناخته‌شده است که در بسیاری از Queryهای معمول از UDP استفاده می‌کند.

💡 تفاوت ساده: TCP روی Reliability و Connection تمرکز دارد، در حالی که UDP سبک‌تر است و Connection را مانند TCP برقرار نمی‌کند.

بررسی Portها با ss

برای دیدن Listening TCP Portها:

Ubuntu 
ss -lnt

برای دیدن UDP:

Ubuntu 
ss -lnu

برای مشاهده Process مرتبط:

Ubuntu 
sudo ss -lntup

این دستور در Troubleshooting بسیار کاربردی است. مثلاً اگر Application روی Port 8080 باید فعال باشد، می‌توان بررسی کرد آیا Port واقعاً Listening است یا خیر.

curl

ابزار curl برای ارتباط با سرویس‌های مختلف و مخصوصاً HTTP/HTTPS بسیار کاربردی است.

مثلاً:

HTTP 
curl http://example.com

برای دیدن Headerها:

HTTP Headers 
curl -I https://example.com

اگر یک Web Server مشکل دارد، curl می‌تواند کمک کند بفهمیم آیا سرویس HTTP واقعاً پاسخ می‌دهد یا خیر.

Netcat

ابزار nc یا Netcat برای تست Connection به یک Port بسیار مفید است.

مثلاً:

Ubuntu 
nc -vz 192.168.1.10 22

این دستور تلاش می‌کند به Port 22 روی Host موردنظر متصل شود.

اگر Port در دسترس نباشد، می‌توانیم نتیجه را برای تشخیص مشکل Network یا Service بررسی کنیم.

Traceroute

گاهی Ping فقط می‌گوید مقصد قابل دسترسی هست یا نیست. اما ممکن است بخواهیم بفهمیم Packet در مسیر از چه Hopهایی عبور می‌کند.

برای این کار می‌توان از:

Ubuntu 
traceroute example.com

استفاده کرد.

اگر روی سیستم نصب نبود:

Ubuntu 
sudo apt install traceroute
⚠️ بعضی Routerها یا Firewallها ممکن است به Probeهای traceroute پاسخ ندهند. بنابراین وجود یک * الزاماً به معنی خراب بودن مسیر نیست.

روش Troubleshooting

فرض کنیم یک Application روی Server داریم و کاربر نمی‌تواند به آن وصل شود. بهتر است بررسی را مرحله‌به‌مرحله انجام دهیم.

مرحله 1 — آیا Server روشن و Interface فعال است؟

Terminal 
ip addr
ip link

مرحله 2 — آیا Route درست است؟

Terminal 
ip route

مرحله 3 — آیا مقصد قابل دسترسی است؟

Terminal 
ping -c 4 SERVER_IP

مرحله 4 — آیا Port باز و Listening است؟

Terminal 
sudo ss -lntp

مرحله 5 — آیا Port از Client قابل دسترسی است؟

Client 
nc -vz SERVER_IP 8080

مرحله 6 — آیا Application پاسخ می‌دهد؟

Client 
curl -I http://SERVER_IP:8080

مرحله 7 — اگر Domain استفاده می‌شود، DNS را بررسی کن

DNS 
dig example.com

تمرین عملی: Network Troubleshooting Lab

🧪 تمرین

ابتدا Portهای Listening سیستم خودت را ببین:

Ubuntu 
sudo ss -lntup

سپس DNS را تست کن:

Ubuntu 
dig example.com

بعد HTTP را بررسی کن:

Ubuntu 
curl -I https://example.com

در نهایت مسیر Network را بررسی کن:

Ubuntu 
ip route
ip route get 8.8.8.8

هدف این تمرین این است که بتوانی تفاوت بین: DNS Problem، Routing Problem، Port Problem و Application Problem را تشخیص بدهی.

Network Troubleshooting Cheat Sheet

Command کاربرد
ip addr بررسی IP
ip route بررسی Routing
ping بررسی Connectivity
ss -lntup بررسی Listening Ports
dig بررسی DNS
curl تست HTTP/HTTPS
nc تست اتصال به Port
traceroute بررسی مسیر تا مقصد

چیزی که از این مرحله یاد گرفتم

  • DNS وظیفه Name Resolution را بر عهده دارد.
  • Port مشخص می‌کند ارتباط مربوط به کدام Endpoint سرویس است.
  • TCP Connection-oriented و قابل اعتماد است.
  • UDP سبک‌تر است و مانند TCP Connection برقرار نمی‌کند.
  • ss برای بررسی Socket و Listening Port بسیار مهم است.
  • dig برای Troubleshooting DNS کاربرد دارد.
  • curl برای تست سرویس‌های HTTP/HTTPS بسیار مفید است.
  • nc برای تست دسترسی به Port کاربرد دارد.
  • traceroute می‌تواند مسیر Hopها تا مقصد را نشان دهد.
