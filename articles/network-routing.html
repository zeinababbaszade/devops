Routing چیست؟

Routing فرآیندی است که مشخص می‌کند یک Packet برای رسیدن به مقصد باید از چه مسیری عبور کند.

اگر دو سیستم در یک Network باشند، ممکن است بتوانند مستقیماً با یکدیگر ارتباط داشته باشند. اما اگر مقصد در Network دیگری باشد، Packet معمولاً باید از Router یا Gateway عبور کند.

💡 یک مفهوم کلیدی: Switch بیشتر در سطح شبکه محلی و Forward کردن Frameها فعالیت می‌کند، در حالی که Router برای ارتباط بین Networkهای مختلف و انتخاب مسیر استفاده می‌شود.

Packet چگونه مسیر خود را پیدا می‌کند؟

فرض کنیم Server ما IP زیر را دارد:

Server 
192.168.1.20/24

و می‌خواهیم به:

Destination 
10.10.10.50

دسترسی پیدا کنیم.

سیستم بررسی می‌کند آیا برای Network مقصد Route مشخصی دارد یا خیر. اگر Route مناسب وجود نداشته باشد، معمولاً Default Route استفاده می‌شود.

Routing Table

Linux برای تصمیم‌گیری درباره مسیر Packetها از Routing Table استفاده می‌کند.

برای مشاهده آن:

Ubuntu Terminal 
ip route

ممکن است خروجی شبیه این باشد:

Example 
default via 192.168.1.1 dev ens160
192.168.1.0/24 dev ens160 proto kernel scope link src 192.168.1.20

Default Route

Default Route مسیری است که وقتی Route دقیق‌تری برای مقصد وجود ندارد، مورد استفاده قرار می‌گیرد.

Example 
default via 192.168.1.1 dev ens160

در اینجا:

  • default یعنی مسیر پیش‌فرض.
  • via 192.168.1.1 یعنی Gateway.
  • dev ens160 یعنی Interface مورد استفاده.

Gateway

Gateway معمولاً Router یا دستگاهی است که Linux می‌تواند Packet را برای مقصدهای خارج از Network محلی به آن تحویل دهد.

مثلاً:

Network 
Server:  192.168.1.20
Gateway: 192.168.1.1

اگر Server بخواهد به:

Remote Network 
10.10.10.50

برسد، Packet می‌تواند به Gateway ارسال شود تا Router آن را به سمت Network مقصد Forward کند.

دستور ip route

برای مشاهده Routeها:

Terminal 
ip route

برای بررسی اینکه Linux برای یک مقصد خاص چه مسیری را انتخاب می‌کند، می‌توانیم از:

Terminal 
ip route get 8.8.8.8

این دستور برای Troubleshooting بسیار مفید است، چون به جای اینکه فقط کل Routing Table را ببینیم، تصمیم سیستم درباره یک مقصد خاص را بررسی می‌کنیم.

Static Route

گاهی لازم است یک Route خاص را به صورت دستی به سیستم اضافه کنیم. به چنین Routeای Static Route می‌گوییم.

مثلاً:

Example 
sudo ip route add 10.20.0.0/16 via 192.168.1.1

یعنی برای Network:

Destination Network 
10.20.0.0/16

از Gateway:

Gateway 
192.168.1.1

استفاده شود.

⚠️ Routeهایی که با ip route add به‌صورت مستقیم اضافه می‌شوند، بسته به روش مدیریت شبکه سیستم ممکن است بعد از Restart باقی نمانند. برای تنظیم دائمی باید از روش مدیریت شبکه همان سیستم مانند Netplan استفاده شود.

Route Selection

Linux معمولاً از طولانی‌ترین Prefix Match برای انتخاب Route مناسب استفاده می‌کند.

مثلاً فرض کنیم Routing Table شامل این موارد باشد:

Routing Table 
10.0.0.0/8
10.10.0.0/16
10.10.20.0/24
default

اگر مقصد:

Destination 
10.10.20.50

باشد، Route مربوط به 10.10.20.0/24 از Route عمومی‌تر 10.10.0.0/16 دقیق‌تر است.

این مفهوم درک Routing را بسیار مهم می‌کند: هرچه Prefix مشخص‌تر باشد، Route دقیق‌تر است.

Troubleshooting Routing

فرض کنیم Server به یک Server دیگر دسترسی ندارد. اولین کار این نیست که Route جدید اضافه کنیم. ابتدا باید وضعیت موجود را بررسی کنیم.

1. بررسی IP

Terminal 
ip addr

2. بررسی Route

Terminal 
ip route

3. بررسی مسیر یک مقصد خاص

Terminal 
ip route get 10.10.10.50

4. بررسی Gateway

Terminal 
ping -c 4 192.168.1.1

تمرین عملی

🧪 Routing Lab

ابتدا Routing Table سیستم خودت را مشاهده کن:

Ubuntu 
ip route

سپس یک مقصد خارجی را بررسی کن:

Ubuntu 
ip route get 8.8.8.8

حالا موارد زیر را پیدا کن:

  • Default Gateway چیست؟
  • Interface مورد استفاده چیست؟
  • Source IP چیست؟
  • برای Network محلی چه Routeای وجود دارد؟

Routing Cheat Sheet

Command کاربرد
ip route نمایش Routing Table
ip route get IP بررسی Route انتخاب‌شده برای مقصد
ip route add افزودن Route
ip route del حذف Route
ping بررسی Connectivity

چیزی که از این مرحله یاد گرفتم

  • Linux برای ارسال Packet از Routing Table استفاده می‌کند.
  • Default Route زمانی استفاده می‌شود که Route دقیق‌تری وجود نداشته باشد.
  • Gateway معمولاً مسیر خروج به Networkهای دیگر است.
  • با ip route get می‌توان مسیر انتخاب‌شده برای یک مقصد خاص را بررسی کرد.
  • Static Route را می‌توان به صورت دستی ایجاد کرد.
  • Prefix دقیق‌تر معمولاً نسبت به Prefix عمومی‌تر اولویت دارد.
