CIDR چیست؟

CIDR مخفف Classless Inter-Domain Routing است.

CIDR روشی برای نمایش IP Network با استفاده از Prefix Length است.

مثلاً:

Example
192.168.1.0/24

Prefix Length

عدد بعد از / تعداد بیت‌هایی را نشان می‌دهد که برای Network Portion استفاده شده‌اند.

مثلاً:

Example
/24

یعنی 24 بیت از 32 بیت IPv4 مربوط به Network Prefix است.

/24

Example
192.168.1.0/24

Subnet Mask:

Example
255.255.255.0

تعداد کل Addressها:

Example
2^(32-24) = 256

و در حالت معمول 254 Host قابل استفاده داریم.

/25

در /25 تعداد بیت‌های Network برابر 25 است.

Example
2^(32-25) = 128

یعنی هر Subnet دارای 128 Address است و معمولاً 126 Host قابل استفاده دارد.

/26

Example
2^(32-26) = 64

در /26 معمولاً 62 Host قابل استفاده داریم.

CIDR در DevOps

CIDR یکی از مفاهیمی است که در محیط‌های واقعی DevOps دائماً می‌بینی.

برای مثال در Cloud ممکن است یک VPC یا Virtual Network به‌صورت زیر تعریف شود:

Example
10.0.0.0/16

و بعد Subnetهای مختلفی داخل آن ساخته شوند:

Example
10.0.1.0/24
10.0.2.0/24
10.0.3.0/24
💡 در Docker و Kubernetes نیز مفاهیم CIDR و Network Range اهمیت زیادی دارند؛ بعداً وقتی سراغ آن‌ها بروم، همین مفاهیم پایه دوباره به کار می‌آیند.

چیزی که از این مرحله یاد گرفتم

  • CIDR روش استاندارد و رایج برای نمایش Network Prefix است.
  • عدد بعد از Slash مشخص می‌کند چند بیت برای Network استفاده شده است.
  • هرچه Prefix بزرگ‌تر باشد (مثلاً /28 نسبت به /24)، تعداد Hostهای قابل استفاده کمتر است.
  • CIDR در تعریف VPC و Subnetهای Cloud هم دائماً استفاده می‌شود.
