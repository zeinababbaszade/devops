چرا User و Group مهم هستند؟

در یک سیستم Linux معمولاً چند User و چند سرویس وجود دارند. هر User باید فقط به منابعی که برای کارش لازم است دسترسی داشته باشد. Groupها هم راهی برای مدیریت مجموعه‌ای از کاربران با Permissionهای مشترک هستند.

💡 یکی از اصول مهم امنیت در DevOps، Least Privilege است؛ یعنی هر User یا سرویس فقط به اندازه نیازش دسترسی داشته باشد.

شناخت User فعلی

برای دیدن User فعلی از whoami استفاده می‌کنیم.

Terminal
whoami

برای دیدن اطلاعات کامل‌تر User و Groupهای او:

Terminal
id

فایل /etc/passwd

اطلاعات پایه حساب‌های کاربری محلی در فایل /etc/passwd ثبت می‌شود. برای مشاهده آن می‌توانیم از دستور زیر استفاده کنیم:

Terminal
cat /etc/passwd

این فایل شامل اطلاعات متنی حساب‌هاست؛ اما به معنی این نیست که Passwordهای واقعی کاربران را باید در آن ببینیم.

ساخت User

در Ubuntu برای ساخت User جدید می‌توان از adduser استفاده کرد.

Terminal
sudo adduser labuser

پس از ساخت، می‌توانیم اطلاعات User را بررسی کنیم:

Terminal
id labuser

Group چیست؟

Group اجازه می‌دهد چند User را در یک مجموعه قرار دهیم و Permissionهای مشترکی برای آن‌ها تعریف کنیم.

Terminal
sudo groupadd devops-lab

برای اضافه کردن User به Group:

Terminal
sudo usermod -aG devops-lab labuser

حالا بررسی می‌کنیم:

Terminal
id labuser
⚠️ در دستور usermod -aG گزینه -a مهم است؛ حذف آن در بعضی سناریوها می‌تواند عضویت‌های قبلی User در Groupها را تحت تأثیر قرار دهد.

تغییر User با su

دستور su برای تغییر User در یک Shell استفاده می‌شود.

Terminal
su - labuser
whoami
exit

sudo چیست؟

sudo اجازه می‌دهد یک User مجاز، یک دستور را با سطح دسترسی بالاتر اجرا کند. برای بسیاری از کارهای مدیریتی Ubuntu به جای ورود دائمی به حساب root از sudo استفاده می‌کنیم.

Terminal
sudo whoami

اگر User فعلی مجوز sudo داشته باشد، خروجی این دستور معمولاً root خواهد بود.

تمرین عملی: Users & Groups Lab

🧪 تمرین

این تمرین را مرحله‌به‌مرحله اجرا کن:

Ubuntu Terminal
sudo groupadd devops-lab
sudo adduser labuser
id labuser
sudo usermod -aG devops-lab labuser
id labuser
su - labuser
whoami
exit

بعد از اضافه کردن User به Group، با id labuser بررسی کن که Group جدید در خروجی دیده می‌شود.

ارتباط User، Group و Permission

حالا ارتباط مباحث دو مقاله قبل مشخص‌تر می‌شود. Permissionهای یک فایل به Owner، Group و Others تقسیم می‌شوند؛ بنابراین User و Group مستقیماً روی دسترسی به فایل‌ها و Directoryها اثر دارند.

Terminal
ls -l notes.txt

اگر Group فایل devops-lab باشد، می‌توان Permissionهای Group را طوری تنظیم کرد که اعضای آن Group دسترسی مشخصی داشته باشند.

اصل Least Privilege

در محیط‌های واقعی DevOps بهتر است Userها و سرویس‌ها بیش از نیازشان دسترسی نداشته باشند. برای مثال یک سرویس وب نباید بدون دلیل به تمام فایل‌های سیستم دسترسی Write داشته باشد.

💡 وقتی Permission خطا می‌دهد، قبل از استفاده از دسترسی‌های بسیار باز، این سه مورد را بررسی کن: چه Userای؟ چه Groupای؟ چه Permissionای؟

Users & Groups Cheat Sheet

Commandکاربرد
whoamiنمایش User فعلی
idنمایش User ID و Groupها
sudo adduser userساخت User
sudo groupadd groupساخت Group
sudo usermod -aG group userافزودن User به Group
su - userتغییر User در Shell
sudo commandاجرای دستور با دسترسی مدیریتی

چیزی که از این مرحله یاد گرفتم

  • می‌توانم User فعلی و Groupهای آن را بررسی کنم.
  • با adduser User ایجاد می‌کنم.
  • با groupadd Group می‌سازم.
  • با usermod -aG User را به Group اضافه می‌کنم.
  • با sudo می‌توانم دستورات مدیریتی را در صورت داشتن مجوز اجرا کنم.
  • Permissionها، Userها و Groupها به‌صورت مستقیم به یکدیگر مرتبط هستند.

مرحله بعدی چیست؟

⚙️ Linux Processes

در مقاله بعدی سراغ Processها می‌روم؛ یعنی برنامه‌هایی که در Linux در حال اجرا هستند و ابزارهایی مثل ps، top، htop، kill و مفهوم PID را بررسی می‌کنم.

🚀 از اینجا به بعد، کم‌کم Linux را از یک مجموعه دستور به یک محیط واقعی برای مدیریت سرویس‌ها و زیرساخت تبدیل می‌کنیم.
