کاربران و گروه‌ها در Linux

آشنایی با Userها، Groupها، مدیریت کاربران و دسترسی‌های sudo در Linux.

مقدمه

Linux یک سیستم‌عامل چندکاربره است. یعنی می‌تواند چندین User داشته باشد و برای هر User دسترسی‌های متفاوتی تعریف کند.

این موضوع در Serverها اهمیت زیادی دارد؛ زیرا معمولاً چندین کاربر، سرویس و Application روی یک سیستم فعالیت می‌کنند.

در این مقاله با User، Group و دستورات مهم مدیریت آن‌ها آشنا می‌شویم.

1. مشاهده کاربر فعلی با whoami

برای اینکه بفهمیم در حال حاضر با چه کاربری وارد سیستم شده‌ایم، از دستور زیر استفاده می‌کنیم: 

whoami

یک دستور مفید دیگر: 

id

دستور id اطلاعات بیشتری مانند UID، GID و گروه‌های کاربر را نمایش می‌دهد.

2. فایل /etc/passwd

اطلاعات حساب‌های کاربری محلی Linux در فایل: 

/etc/passwd

قرار دارد.

می‌توانیم محتوای آن را مشاهده کنیم: 

cat /etc/passwd

برای پیدا کردن یک User خاص: 

grep username /etc/passwd
نکته امنیتی:

بهتر است فایل‌های سیستمی مانند /etc/passwd را مستقیماً ویرایش نکنیم و برای مدیریت کاربران از دستورات استاندارد Linux استفاده کنیم.

3. ایجاد User جدید

در Ubuntu می‌توانیم با دستور adduser یک User جدید ایجاد کنیم. 

sudo adduser devopsuser

سیستم از ما رمز عبور و اطلاعات دیگری درباره کاربر خواهد پرسید.

بعد از ایجاد کاربر می‌توانیم آن را بررسی کنیم: 

id devopsuser

Home Directory کاربر نیز معمولاً در مسیر زیر قرار می‌گیرد: 

/home/devopsuser

4. جابه‌جایی بین کاربران

برای ورود به محیط یک User دیگر می‌توانیم از su استفاده کنیم: 

su - devopsuser

برای بازگشت به User قبلی: 

exit

5. Group چیست؟

Group در Linux راهی برای مدیریت مجموعه‌ای از کاربران است.

به جای اینکه Permission یک فایل را برای تک‌تک کاربران تنظیم کنیم، می‌توانیم کاربران را در یک Group قرار دهیم و Permission را برای Group تنظیم کنیم.

برای مشاهده گروه‌های کاربر فعلی: 

groups

یا: 

id

6. ایجاد Group

برای ایجاد یک Group جدید از groupadd استفاده می‌کنیم: 

sudo groupadd devops

برای بررسی Group: 

getent group devops

7. اضافه کردن User به Group

برای اضافه کردن یک User به Group: 

sudo usermod -aG devops devopsuser

قسمت -aG مهم است.

گزینه -a یعنی اضافه کردن بدون حذف عضویت‌های قبلی، و -G گروه‌های تکمیلی User را مشخص می‌کند.

برای بررسی: 

id devopsuser
نکته:

بعد از تغییر Groupهای یک User، ممکن است لازم باشد User یک Login Session جدید ایجاد کند تا تغییرات در Session جدید اعمال شوند.

8. sudo چیست؟

بعضی عملیات در Linux نیاز به دسترسی مدیریتی دارند.

دستور sudo به یک User مجاز اجازه می‌دهد یک دستور را با دسترسی بالاتر اجرا کند. 

sudo apt update

مثال دیگر: 

sudo systemctl status ssh

در محیط‌های DevOps استفاده از sudo بسیار رایج است.

9. دستورات مهم مدیریت User و Group

دستور کاربرد
whoami نمایش User فعلی
id نمایش UID، GID و Groupها
groups نمایش Groupهای User
adduser ایجاد User
groupadd ایجاد Group
usermod تغییر مشخصات User
passwd تغییر Password
su تغییر User
sudo اجرای دستور با دسترسی مدیریتی

10. تمرین عملی

حالا یک User و Group آزمایشی ایجاد می‌کنیم.

مرحله اول — ایجاد Group

sudo groupadd devops-lab

مرحله دوم — ایجاد User

sudo adduser labuser

مرحله سوم — بررسی User

id labuser

مرحله چهارم — اضافه کردن User به Group

sudo usermod -aG devops-lab labuser

مرحله پنجم — بررسی Group

id labuser

باید Group devops-lab را در خروجی مشاهده کنی.

مرحله ششم — ورود به User جدید

su - labuser

مرحله هفتم — بررسی User فعلی

whoami

خروجی باید: 

labuser

مرحله هشتم — خروج

exit
تمرین پیشنهادی:

بعد از انجام تمرین، دستورهای whoami، id و groups را هم با User اصلی و هم با User آزمایشی اجرا کن و تفاوت خروجی‌ها را بررسی کن.

11. چرا User و Group در DevOps مهم هستند؟

در یک Server واقعی ممکن است افراد و سرویس‌های مختلفی به سیستم دسترسی داشته باشند.

برای مثال:

  • System Administrator
  • Developer
  • Deployment User
  • Monitoring Service
  • Application User

دادن دسترسی کامل به همه کاربران می‌تواند یک مشکل امنیتی جدی ایجاد کند.

به همین دلیل در محیط‌های حرفه‌ای از مفهوم Least Privilege استفاده می‌کنیم؛ یعنی هر User یا Service فقط به اندازه‌ای که نیاز دارد دسترسی داشته باشد.

چیزی که در این مقاله یاد گرفتم

  • مفهوم User در Linux
  • مشاهده User فعلی با whoami
  • بررسی اطلاعات User با id
  • ایجاد User با adduser
  • مفهوم Group
  • ایجاد Group با groupadd
  • اضافه کردن User به Group
  • استفاده از sudo
  • مفهوم Least Privilege
