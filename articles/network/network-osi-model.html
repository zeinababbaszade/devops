OSI Model — 7 Layers

مقدمه

مدل OSI یک مدل مفهومی هفت‌لایه برای تحلیل ارتباطات شبکه است. هدف آن این نیست که Linux دقیقاً هفت نرم‌افزار جدا اجرا کند؛ هدف این است که جریان ارتباط را به اجزای قابل فهم تقسیم کنیم.

Layer 1 — Physical

Physical با بیت، سیگنال، کابل مسی، فیبر، رادیو، Link Speed و Duplex سروکار دارد. در Troubleshooting، Link Down و خطاهای فیزیکی معمولاً از این لایه شروع می‌شوند.

Layer 2 — Data Link

Ethernet Frame، MAC Address، Switch و VLAN مفاهیم اصلی‌اند. Switch بر اساس Source MAC یاد می‌گیرد و بر اساس Destination MAC Forward می‌کند.

Layer 3 — Network

IP، Packet، Router و Routing Table در این لایه قرار دارند. Prefix مقصد تعیین می‌کند Packet باید از کدام مسیر عبور کند.

Layer 4 — Transport

TCP و UDP و Portها در این لایه‌اند. TCP Reliability، Ordering و Congestion/Flow Control ارائه می‌دهد؛ UDP Datagram بدون این تضمین‌های داخلی است.

Layer 5 — Session

Session ایجاد، نگهداری و پایان ارتباط منطقی را مدل می‌کند. در Stackهای مدرن این وظایف اغلب داخل Application یا کتابخانه‌ها پخش شده‌اند.

Layer 6 — Presentation

Encoding، Serialization، Compression و Encryption از مفاهیم این لایه‌اند. مرز دقیق آن در TCP/IP مستقل نیست.

Layer 7 — Application

HTTP، DNS، SSH و SMTP نمونه‌هایی هستند که Applicationها مستقیماً با آن‌ها کار می‌کنند.

Encapsulation

داده از Application به Transport و سپس IP و Link می‌رود و هر لایه اطلاعات لازم خود را اضافه می‌کند. مقصد این Headerها را مرحله‌به‌مرحله باز می‌کند.

Troubleshooting

اگر curl شکست خورد، فقط به HTTP نگاه نکنید: DNS، IP، Route، TCP، TLS و در نهایت Application را به‌ترتیب بررسی کنید.

🧪 Lab عملی

تمرین مرحله‌ای

در Ubuntu این دستورات را اجرا کنید و برای هر خروجی یک جمله توضیح بنویسید. هدف، فهمیدن رابطه بین تئوری و وضعیت واقعی سیستم است.

Ubuntu
ip addr
ip route
ss -lntup
ping -c 4 1.1.1.1
curl -I https://example.com

اگر دستوری خطا داد، متن خطا را ثبت کنید و مشخص کنید مشکل احتمالاً در کدام بخش است: Interface/IP، Routing، DNS، Transport، TLS یا Application.

🎯 چه چیزی یاد گرفتیم؟

  • مفهوم و اجزای اصلی این مبحث را شناختیم.
  • یک روش عملی برای مشاهده یا Troubleshooting آن در Linux یاد گرفتیم.
  • ارتباط آن با DevOps، Cloud، Server و Monitoring را درک کردیم.
نکته DevOps: این مبحث را فقط حفظ نکنید. در Lab خود خروجی واقعی Linux را با مدل ذهنی Networking مقایسه کنید؛ این کار بعدها در Docker، Kubernetes، Cloud و Incident Troubleshooting بسیار ارزشمند است.
