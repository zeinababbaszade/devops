IP Address چیست؟

IP Address یا Internet Protocol Address یک آدرس منطقی است که برای شناسایی یک Interface در شبکه استفاده می‌شود. در یک شبکه، دستگاه‌ها برای برقراری ارتباط باید بدانند بسته اطلاعاتی را به کدام مقصد ارسال کنند. برای مثال:

Example 
192.168.1.10

این آدرس به تنهایی فقط یک عدد نیست؛ بلکه بخشی از یک ساختار شبکه است. وقتی یک Server می‌خواهد با Server دیگری ارتباط برقرار کند، سیستم‌عامل ابتدا بررسی می‌کند که مقصد در کدام Network قرار دارد و سپس بر اساس Routing Table تصمیم می‌گیرد Packet را از کدام Interface ارسال کند.

نکته مهم: MAC Address بیشتر در ارتباطات Layer 2 استفاده می‌شود، در حالی که IP Address در Layer 3 قرار دارد و برای ارتباط بین شبکه‌های مختلف و Routing استفاده می‌شود.

IPv4 چیست؟

IPv4 چهارمین نسخه پروتکل Internet Protocol است و هنوز یکی از رایج‌ترین پروتکل‌های شبکه محسوب می‌شود. IPv4 دارای:

  • 32 بیت
  • 4 Octet
  • هر Octet بین 0 تا 255
  • نمایش معمول به صورت Decimal

مثلاً:

IPv4 
192.168.1.10

در حالت Binary همین Address به شکل زیر است:

Binary 
11000000.10101000.00000001.00001010

هر Octet برابر با 8 بیت است:

IPv4 Structure 
8 bits + 8 bits + 8 bits + 8 bits
   32 bits total

ساختار IPv4 و مفهوم Network و Host

یک IP Address معمولاً از دو قسمت منطقی تشکیل می‌شود:

  • Network Portion: مشخص می‌کند Address متعلق به کدام Network است.
  • Host Portion: دستگاه مشخص داخل آن Network را مشخص می‌کند.

مثلاً اگر داشته باشیم:

Example 
192.168.1.10/24

در /24، تعداد 24 بیت برای Network استفاده شده و 8 بیت باقی‌مانده برای Host است. بنابراین:

Network 
Network: 192.168.1.0
Host:    10
Mask:    255.255.255.0

Subnet Mask و CIDR

Subnet Mask مشخص می‌کند کدام قسمت IP مربوط به Network و کدام قسمت مربوط به Host است. برای مثال:

CIDR Subnet Mask تعداد کل Address
/8 255.0.0.0 16,777,216
/16 255.255.0.0 65,536
/24 255.255.255.0 256
/25 255.255.255.128 128
/26 255.255.255.192 64
/27 255.255.255.224 32
/28 255.255.255.240 16

در بسیاری از Subnetهای IPv4 معمولی، همه Addressها قابل اختصاص مستقیم به Host نیستند؛ Network Address و Broadcast Address معمولاً رزرو هستند. مثلاً در:

/24 
192.168.1.0/24
  • Network Address: 192.168.1.0
  • First Host: 192.168.1.1
  • Last Host: 192.168.1.254
  • Broadcast: 192.168.1.255
اشتباه رایج: این تصور که /24 یعنی «24 تا IP» اشتباه است. /24 یعنی 24 بیت Network و در IPv4 یعنی 256 Address در کل آن Subnet.

Subnetting به زبان ساده

Subnetting یعنی تقسیم یک Network بزرگ‌تر به چند Network کوچک‌تر. فرض کنید یک Network داریم:

Network 
192.168.1.0/24

اگر آن را به /26 تقسیم کنیم، چهار Subnet خواهیم داشت:

Subnet Range
192.168.1.0/26 0 - 63
192.168.1.64/26 64 - 127
192.168.1.128/26 128 - 191
192.168.1.192/26 192 - 255

این مفهوم در طراحی Networkهای سازمانی، Cloud، Kubernetes و حتی Docker Networking بسیار مهم است.

Public و Private IP

همه IPv4 Addressها برای استفاده مستقیم روی Internet طراحی نشده‌اند. سه محدوده معروف Private IPv4 عبارت‌اند از:

Range کاربرد
10.0.0.0/8 Private Network
172.16.0.0/12 Private Network
192.168.0.0/16 Private Network

برای مثال یک Server داخل شبکه سازمان می‌تواند داشته باشد:

Private IP 
10.20.30.15

اما برای ارتباط مستقیم از Internet معمولاً یک Public IP یا سازوکار دیگری مانند Reverse Proxy، Load Balancer یا NAT مورد نیاز است.

Default Gateway چیست؟

اگر مقصد در Network محلی سیستم نباشد، سیستم باید Packet را به یک Router تحویل دهد. آدرس این Router معمولاً به عنوان Default Gateway شناخته می‌شود. مثلاً:

Example 
IP Address:     192.168.1.20
Subnet Mask:    255.255.255.0
Gateway:        192.168.1.1

اگر سیستم بخواهد به:

Remote Destination 
8.8.8.8

دسترسی پیدا کند، مقصد خارج از Network محلی است؛ بنابراین سیستم Packet را به Default Gateway ارسال می‌کند.

Routing و Routing Table

Routing یعنی تصمیم‌گیری درباره اینکه یک Packet برای رسیدن به مقصد از چه مسیری عبور کند. Linux این اطلاعات را در Routing Table نگهداری می‌کند. برای مشاهده:

Ubuntu 
ip route

ممکن است خروجی شبیه این باشد:

Example 
default via 192.168.1.1 dev ens33
192.168.1.0/24 dev ens33 proto kernel scope link

خط اول Default Route است. یعنی اگر مسیر دقیق‌تری برای مقصد وجود نداشته باشد، Packet به Gateway یعنی 192.168.1.1 ارسال می‌شود.

DHCP چیست؟

DHCP یا Dynamic Host Configuration Protocol وظیفه دارد تنظیمات شبکه را به صورت خودکار در اختیار Client قرار دهد. معمولاً شامل:

  • IP Address
  • Subnet Mask / Prefix
  • Default Gateway
  • DNS Server

فرآیند معروف DHCP در IPv4 معمولاً با چهار مرحله شناخته می‌شود:

  1. DHCP Discover
  2. DHCP Offer
  3. DHCP Request
  4. DHCP Acknowledgement

به این فرآیند گاهی DORA نیز گفته می‌شود.

NAT چیست؟

NAT یا Network Address Translation اجازه می‌دهد Addressهای Private از طریق یک Public IP با شبکه‌های بیرونی ارتباط برقرار کنند. یک مثال ساده:

Internal Network 
Client:
192.168.1.20

Router:
Public IP = 203.0.113.10

وقتی Client به Internet متصل می‌شود، Router می‌تواند Source Address را ترجمه کند. در بسیاری از شبکه‌های خانگی و سازمانی، این کار با PAT و استفاده از Portها انجام می‌شود.

نکته DevOps: وقتی Docker، Kubernetes، Cloud و Load Balancer را یاد بگیرید، مفاهیمی مانند NAT، Private IP، Public IP و Routing مرتباً دوباره ظاهر می‌شوند.

IPv6 چیست؟

IPv6 نسخه جدیدتر Internet Protocol است که برای حل محدودیت فضای Address در IPv4 طراحی شده است. IPv6 دارای:

  • 128 بیت
  • نمایش Hexadecimal
  • فضای Address بسیار بزرگ
  • پشتیبانی گسترده از Auto Configuration
  • عدم استفاده از Broadcast

یک IPv6 Address نمونه:

IPv6 
2001:db8:1234:5678:0000:0000:0000:0010

ساختار IPv6

IPv6 از هشت گروه تشکیل شده است و هر گروه چهار رقم Hexadecimal دارد. مثلاً:

IPv6 Structure 
2001:0db8:1234:5678:0000:0000:0000:0001
 |     |    |    |    |    |    |    |
 16    16   16   16   16   16   16   16 bits

Total = 128 bits

فشرده‌سازی IPv6

برای کوتاه‌تر شدن IPv6 دو قانون مهم وجود دارد. قانون اول: صفرهای ابتدایی هر گروه را می‌توان حذف کرد.

Before 
2001:0db8:0001:0000:0000:0000:0000:0001
After 
2001:db8:1:0:0:0:0:1

قانون دوم: یک توالی متوالی از گروه‌های کاملاً صفر را می‌توان با :: جایگزین کرد.

Compressed IPv6 
2001:db8:1::1
نکته مهم: از :: فقط یک بار در یک IPv6 Address استفاده می‌شود؛ چون در غیر این صورت مشخص نیست چند گروه صفر حذف شده‌اند.

انواع IPv6 Address

Global Unicast

این Addressها برای ارتباطات عمومی IPv6 استفاده می‌شوند و محدوده معروف آن‌ها:

IPv6 Global Unicast 
2000::/3

Link-Local

Link-Local برای ارتباط در همان Local Link استفاده می‌شود. محدوده آن:

IPv6 Link-Local 
fe80::/10

در بسیاری از سیستم‌های IPv6-enabled می‌توانید Link-Local Address را روی Interface مشاهده کنید.

Unique Local Address

برای شبکه‌های خصوصی IPv6 از Unique Local Address استفاده می‌شود. محدوده:

IPv6 ULA 
fc00::/7

Loopback

Loopback در IPv6 برابر است با:

Loopback 
::1

SLAAC و DHCPv6

یکی از ویژگی‌های مهم IPv6 امکان Auto Configuration است. در SLAAC یا Stateless Address Autoconfiguration، Host می‌تواند با استفاده از اطلاعات شبکه، Address خودش را ایجاد کند. همچنین DHCPv6 می‌تواند برای ارائه اطلاعات بیشتر یا مدیریت تنظیمات شبکه استفاده شود.

نکته: در IPv6 نباید تصور کنیم DHCPv6 دقیقاً جایگزین DHCPv4 است. مدل Configuration در IPv6 می‌تواند بر اساس SLAAC، DHCPv6 یا ترکیبی از آن‌ها طراحی شود.

NDP و Neighbor Discovery

در IPv4 پروتکل ARP برای پیدا کردن MAC Address مربوط به یک IPv4 Address استفاده می‌شود. IPv6 از ARP استفاده نمی‌کند. در IPv6 وظیفه Neighbor Discovery توسط ICMPv6 و NDP انجام می‌شود.

NDP برای مواردی مانند:

  • Neighbor Discovery
  • Router Discovery
  • Router Advertisement
  • Neighbor Advertisement
  • تشخیص برخی مشکلات Neighbor

استفاده می‌شود.

تفاوت IPv4 و IPv6

ویژگی IPv4 IPv6
Address Size 32 bit 128 bit
نمایش Decimal Hexadecimal
Broadcast دارد ندارد
ARP دارد ندارد
Neighbor Discovery ARP NDP / ICMPv6
Loopback 127.0.0.1 ::1
Private Range RFC1918 ULA

IP Address در Linux

در Linux ابزار اصلی برای مشاهده و مدیریت Network Configuration دستور ip است. برای مشاهده Interfaceها:

Linux 
ip link

برای مشاهده IPv4 و IPv6:

Linux 
ip addr

برای مشاهده Routing Table:

Linux 
ip route
ip -6 route

برای مشاهده Addressهای IPv4:

Linux 
ip -4 addr

و برای IPv6:

Linux 
ip -6 addr

🧪 Lab عملی

تمرین 1 — پیدا کردن IP سیستم

در Ubuntu دستور زیر را اجرا کنید:

Ubuntu 
ip addr

Interface فعال خود را پیدا کنید و موارد زیر را یادداشت کنید:

  • نام Interface
  • IPv4 Address
  • Prefix
  • IPv6 Address
  • MAC Address

تمرین 2 — پیدا کردن Gateway

Ubuntu 
ip route

خطی که با default شروع می‌شود را پیدا کنید. مثلاً:

Example 
default via 192.168.1.1 dev ens33

در این مثال:

  • Gateway = 192.168.1.1
  • Interface = ens33

تمرین 3 — تست Local Network

Ubuntu 
ping -c 4 192.168.1.1

اگر پاسخ دریافت کردید، ارتباط با Gateway برقرار است. اگر پاسخ دریافت نشد، این به تنهایی ثابت نمی‌کند که Gateway قطع است؛ ممکن است ICMP روی مقصد Block شده باشد.

تمرین 4 — تست Internet

Ubuntu 
ping -c 4 1.1.1.1

اگر این تست موفق بود ولی:

DNS Test 
ping -c 4 google.com

موفق نشد، یکی از مواردی که باید بررسی کنید DNS است.

تمرین 5 — بررسی DNS

Ubuntu 
resolvectl status
getent hosts google.com

تمرین 6 — مشاهده IPv6

Ubuntu 
ip -6 addr
ip -6 route

بررسی کنید آیا سیستم شما IPv6 Address دارد یا خیر. اگر Addressای با fe80:: مشاهده کردید، آن یک Link-Local Address است.

🔧 روش Troubleshooting مشکل IP

یکی از مهم‌ترین مهارت‌های DevOps این است که وقتی یک Server به مقصدی دسترسی ندارد، بدون حدس زدن مرحله‌به‌مرحله مشکل را پیدا کنیم. یک ترتیب مناسب:

  1. بررسی Interface
  2. بررسی IP Address
  3. بررسی Subnet / Prefix
  4. بررسی Default Gateway
  5. بررسی Routing Table
  6. بررسی DNS
  7. بررسی Firewall
  8. بررسی Service و Port

مثلاً:

Troubleshooting 
ip link
ip addr
ip route
ping -c 4 <gateway>
ping -c 4 1.1.1.1
getent hosts google.com
ss -lntup
یک نکته مهم در Troubleshooting: اگر ping 1.1.1.1 جواب نداد، نباید بلافاصله نتیجه بگیریم «DNS مشکل دارد». در این حالت هنوز ممکن است مشکل از Interface، IP، Gateway، Routing، Firewall یا Internet Connectivity باشد. DNS زمانی منطقی‌تر مطرح می‌شود که ارتباط IP برقرار باشد اما Resolution نام انجام نشود.
