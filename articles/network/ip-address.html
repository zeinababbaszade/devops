IP Address چیست؟

IP Address یا Internet Protocol Address یک آدرس منطقی برای شناسایی یک Interface در یک شبکه IP است.

اگر MAC Address را در مقاله قبلی به عنوان یکی از مفاهیم Layer 2 در نظر بگیریم، IP Address در Layer 3 قرار دارد.

وظیفه اصلی IP این است که به Network Stack کمک کند بفهمد:

  • مبدأ Packet کجاست؟
  • مقصد Packet کجاست؟
  • آیا مقصد در همین Network است؟
  • اگر مقصد در Network دیگری است، Packet باید به کدام Router یا Gateway ارسال شود؟

برای مثال:

Example 
Client:
192.168.1.10

Server:
192.168.1.20

این دو Host ممکن است در یک شبکه محلی باشند و مستقیماً با یکدیگر ارتباط برقرار کنند. اما اگر Server دارای IP زیر باشد: 

10.10.20.50
احتمالاً مقصد در Network دیگری قرار دارد و Router باید در مسیر قرار بگیرد.
مدل ذهنی مهم: MAC بیشتر برای ارتباط محلی و Frame در Layer 2 استفاده می‌شود، در حالی که IP برای Addressing و Routing در Layer 3 استفاده می‌شود.

Network و Host چیستند؟

یکی از مهم‌ترین مفاهیمی که قبل از Subnetting باید یاد بگیریم، تفاوت بین Network و Host است.

فرض کنیم IP زیر را داریم: 

192.168.1.25/24

قسمت /24 مشخص می‌کند که 24 بیت اول مربوط به Network Prefix است. در نتیجه: 

Network:
192.168.1.0

Host:
25

البته این بیان ساده‌شده است؛ در واقع Host Portion شامل بیت‌هایی است که توسط Prefix برای Host باقی مانده‌اند.

با /24: 

IPv4 = 32 bits

Network = 24 bits
Host    = 8 bits

پس تعداد بیت‌های Host برابر است با: 

32 - 24 = 8

و تعداد کل حالت‌های آدرس Host در آن Subnet برابر است با: 

2^8 = 256 addresses

در Subnetهای معمول IPv4، همه این 256 آدرس الزاماً برای Hostها قابل استفاده نیستند؛ Network Address و Broadcast Address کاربردهای ویژه دارند.

IPv4 و ساختار آن

IPv4 یک Address برابر با 32 بیت است. برای خوانایی، این 32 بیت به چهار بخش 8 بیتی تقسیم می‌شود. 

8 bits    8 bits    8 bits    8 bits

  192       168        1         25

هر بخش را Octet می‌نامیم. بنابراین یک IPv4 Address چهار Octet دارد.

مقدار محدوده
هر Octet 0 تا 255
کل IPv4 32 بیت
تعداد کل IPv4 Addressها 2³² ≈ 4.29 میلیارد

مثال Binary

IP زیر را در نظر بگیر: 

192.168.1.10

نمایش Binary آن: 

192       168       1         10

11000000  10101000  00000001  00001010

درک Binary در ابتدا کمی سخت است، اما هنگام یادگیری Subnetting بسیار مهم خواهد شد.

Subnet Mask چیست؟

Subnet Mask مشخص می‌کند کدام بخش از IPv4 Address مربوط به Network است و کدام بخش برای Host باقی می‌ماند.

مثلاً: 

IP Address:
192.168.1.25

Subnet Mask:
255.255.255.0

در Binary: 

IP:
11000000.10101000.00000001.00011001

Mask:
11111111.11111111.11111111.00000000

قسمت‌هایی که Mask در آن‌ها 1 است، Network Portion هستند. قسمت‌هایی که 0 هستند، Host Portion هستند.

برای Mask برابر با 255.255.255.0 داریم:

Network = 24 bits
Host = 8 bits

چند Subnet Mask رایج

CIDR Subnet Mask تعداد کل Address
/8 255.0.0.0 16,777,216
/16 255.255.0.0 65,536
/24 255.255.255.0 256
/25 255.255.255.128 128
/26 255.255.255.192 64
/27 255.255.255.224 32
/28 255.255.255.240 16
/30 255.255.255.252 4

CIDR چیست؟

CIDR مخفف Classless Inter-Domain Routing است. در شبکه‌های امروزی معمولاً به جای نوشتن کامل Subnet Mask، از Prefix Length استفاده می‌کنیم.

مثلاً: 

192.168.1.25/24

یعنی 24 بیت اول برای Network Prefix در نظر گرفته شده است.

مثال دیگر: 

10.10.20.15/16

در اینجا: 

Network bits = 16
Host bits    = 16

و تعداد کل Addressها: 

2^16 = 65,536
CIDR را خیلی جدی بگیر. در ادامه مسیر DevOps، CIDR را در:

VPC → Cloud → Kubernetes → Docker → Firewall → Routing → Security Groups بارها خواهی دید.

Network Address و Broadcast Address

یکی از مهم‌ترین مباحث Subnetting، تشخیص Network Address و Broadcast Address است.

فرض کنیم: 

192.168.1.25/24

برای /24: 

Network:
192.168.1.0

First usable:
192.168.1.1

Last usable:
192.168.1.254

Broadcast:
192.168.1.255

بنابراین در یک Subnet معمول /24:

  • 192.168.1.0 → Network Address
  • 192.168.1.1 تا 192.168.1.254 → معمولاً Host Address
  • 192.168.1.255 → Broadcast Address
⚠️ این قاعده را به صورت کورکورانه برای همه Prefixها استفاده نکن. در IPv4، رفتار آدرس‌های قابل استفاده به Prefix و نوع کاربرد Subnet بستگی دارد؛ همچنین در Point-to-Point و بعضی سناریوهای خاص، قواعد عملی می‌توانند متفاوت باشند.

Private و Public IP

همه IPv4 Addressها مستقیماً روی Internet قابل استفاده نیستند. یکی از مفاهیم مهم، Private IP است. محدوده‌های Private IPv4 طبق RFC 1918 عبارت‌اند از:

Range CIDR
10.0.0.0 – 10.255.255.255 10.0.0.0/8
172.16.0.0 – 172.31.255.255 172.16.0.0/12
192.168.0.0 – 192.168.255.255 192.168.0.0/16

این Addressها معمولاً در شبکه‌های داخلی استفاده می‌شوند. برای مثال: 

Server:
192.168.10.20

Database:
192.168.10.30

Gateway:
192.168.10.1

برای دسترسی Hostهای Private به Internet معمولاً از تکنیک‌هایی مانند NAT استفاده می‌شود.

Special IP Addresses

Loopback

در IPv4 محدوده 127.0.0.0/8 برای Loopback رزرو شده است. معروف‌ترین Address آن: 

127.0.0.1

این Address برای ارتباط سیستم با خودش استفاده می‌شود. مثلاً: 

curl http://127.0.0.1:8080

0.0.0.0

0.0.0.0 در IPv4 در چند Context مختلف استفاده می‌شود. یکی از کاربردهای بسیار مهم آن در Serverها، Bind کردن یک سرویس روی همه Interfaceهای IPv4 سیستم است. مثلاً: 

0.0.0.0:8080

یعنی سرویس از همه Interfaceهای IPv4 که مناسب باشند قابل دسترسی است، نه اینکه خود 0.0.0.0 یک IP واقعی برای اتصال به Server باشد.

APIPA

در بعضی محیط‌های IPv4، اگر سیستم نتواند از DHCP آدرس دریافت کند، ممکن است Addressی از محدوده: 

169.254.0.0/16
دریافت کند. این نوع Address را معمولاً Link-Local / APIPA می‌نامیم.

Default Gateway چیست؟

فرض کن کامپیوتر ما: 

IP:
192.168.1.20/24

و می‌خواهیم با: 

8.8.8.8
ارتباط برقرار کنیم. این مقصد در همان Subnet محلی نیست. بنابراین سیستم باید Packet را به Default Gateway ارسال کند. مثلاً: 

Default Gateway:
192.168.1.1

Router سپس تصمیم می‌گیرد Packet را از کدام مسیر Forward کند. 

Client
192.168.1.20
      |
      | Packet
      v
Gateway
192.168.1.1
      |
      v
Router / Internet
      |
      v
8.8.8.8
این دقیقاً جایی است که مفاهیم مقاله قبلی یعنی MAC + ARP با IP به یکدیگر متصل می‌شوند. اگر مقصد خارج از Subnet باشد، Host معمولاً Frame را به MAC مربوط به Next Hop یا Default Gateway ارسال می‌کند، نه MAC سرور نهایی Internet.

DHCP و Static IP

یک سیستم می‌تواند IP را به صورت دستی یا خودکار دریافت کند.

Static IP

در Static Configuration، IP، Prefix و معمولاً Gateway و DNS را به صورت مشخص تنظیم می‌کنیم. برای Serverها، Static یا Reservation-based addressing در بسیاری از محیط‌ها رایج است، چون آدرس سرویس باید قابل پیش‌بینی باشد.

DHCP

در DHCP، Client برای دریافت تنظیمات Network با DHCP Server ارتباط برقرار می‌کند. معمولاً اطلاعاتی مانند:

  • IP Address
  • Subnet Mask / Prefix
  • Default Gateway
  • DNS Server

به Client ارائه می‌شود.

فرآیند معروف DHCP را می‌توان به شکل زیر خلاصه کرد: 

Discover
    ↓
Offer
    ↓
Request
    ↓
ACK

IPv6 چیست؟

IPv4 با وجود کاربرد گسترده، فضای Addressing محدودی دارد. برای حل مشکلات مختلف از جمله گسترش فضای Address، IPv6 طراحی شد.

IPv6 دارای: 

128 bits

است. یک IPv6 Address نمونه: 

2001:db8:1234:5678:abcd:1234:5678:9abc

IPv6 به صورت گروه‌های Hexadecimal نمایش داده می‌شود.

Loopback در IPv6 

::1

معادل مفهومی Loopback در IPv4 یعنی 127.0.0.1 است.

Unspecified Address 

::

این Address در IPv6 نقش Unspecified Address را دارد.

Link-Local IPv6

IPv6 برای Link-Local Addressها از محدوده: 

fe80::/10

استفاده می‌کند.

در مسیر DevOps لازم نیست در اولین مرحله IPv6 را کامل یاد بگیری، اما باید بتوانی IPv6 Addressها را تشخیص بدهی و مفاهیمی مانند fe80::، ::1 و Prefixها را بشناسی.

IP Address در Linux

در Linux ابزار اصلی برای مدیریت و مشاهده Network Configuration، دستور ip است.

مشاهده IPها

Ubuntu 
ip addr

یا: 

ip a

برای مشاهده Interface خاص: 

ip addr show ens33

مشاهده Route 

ip route

مشاهده Neighbor 

ip neigh

مشاهده وضعیت Interface 

ip link

Routing و IP Address

داشتن IP به تنهایی به معنی داشتن ارتباط کامل با Network نیست. سیستم باید بداند Packet را از کدام Interface و به سمت کدام Next Hop ارسال کند. این اطلاعات در Routing Table قرار دارد.

با دستور زیر Routing Table را ببین: 

ip route

یک خروجی نمونه: 

default via 192.168.1.1 dev ens33
192.168.1.0/24 dev ens33 proto kernel scope link

خط اول: 

default via 192.168.1.1 dev ens33

یعنی برای مقصدهایی که Route دقیق‌تری وجود ندارد، Gateway برابر 192.168.1.1 و Interface برابر ens33 است.

Routing بر اساس Prefix انجام می‌شود. این مفهوم در آینده برای یادگیری:

Static Route → OSPF → BGP → Cloud Routing → Kubernetes Networking

بسیار مهم خواهد بود.

Troubleshooting با IP Address

یکی از مهارت‌های مهم DevOps این است که وقتی یک Server یا Application ارتباط ندارد، بدانیم از کجا شروع کنیم.

مرحله اول — Interface 

ip link

بررسی کن Interface فعال است یا نه.

مرحله دوم — IP 

ip addr

بررسی کن Interface موردنظر IP مناسب دارد یا خیر.

مرحله سوم — Routing 

ip route

بررسی کن Default Route یا Route مقصد وجود دارد یا خیر.

مرحله چهارم — Gateway 

ping -c 4 192.168.1.1

اگر Gateway قابل دسترسی نیست، قبل از رفتن سراغ DNS و Application باید Network محلی را بررسی کنیم.

مرحله پنجم — Internet Connectivity 

ping -c 4 1.1.1.1

اگر IP مقصد قابل دسترسی است ولی Domain کار نمی‌کند، احتمال دارد مشکل مربوط به DNS باشد.

مرحله ششم — DNS 

dig example.com

یا: 

getent hosts example.com

مرحله هفتم — Application 

curl -v https://example.com

اینجا دیگر وارد لایه‌های بالاتر می‌شویم.

مدل Troubleshooting:

Interface
↓ IP
↓ ARP / Neighbor
↓ Route
↓ Gateway
↓ DNS
↓ TCP/UDP
↓ TLS
↓ Application

کاربرد IP Address در DevOps

IP Address تقریباً در تمام بخش‌های Infrastructure و DevOps حضور دارد.

Linux Server

هر Server معمولاً چند Interface یا Address دارد و Serviceها ممکن است روی IP مشخصی Bind شوند.

Docker

Containerها معمولاً IP داخلی دارند. در Docker Networking، Bridge Network، Container IP، Gateway، NAT و Port Mapping به یکدیگر مرتبط هستند.

Kubernetes

در Kubernetes با چند سطح Addressing مواجه می‌شوی:

  • Pod IP
  • Service IP
  • Node IP
  • Cluster Network
  • Service Network

بنابراین فهم IP و CIDR برای Kubernetes کاملاً ضروری است.

Cloud

در Cloud Providerها، CIDR و IP را در مفاهیمی مانند:

  • VPC
  • Subnet
  • Route Table
  • Security Group
  • Load Balancer
  • Private Endpoint

خواهی دید.

Monitoring

در ابزارهایی مثل Zabbix و Grafana، IP Address معمولاً یکی از اطلاعات اصلی برای ارتباط با Hostها، Agentها، SNMP، HTTP Endpointها و سرویس‌های مختلف است.

🎯 چه چیزی یاد گرفتیم؟

  • IP Address یک آدرس منطقی در Layer 3 است.
  • IPv4 دارای 32 بیت و IPv6 دارای 128 بیت است.
  • Subnet Mask مشخص می‌کند چه بخشی از Address مربوط به Network است.
  • CIDR روش رایج نمایش Prefix Length است.
  • Network Address و Broadcast Address مفاهیم مهم IPv4 Subnetting هستند.
  • Private IPها برای شبکه‌های داخلی استفاده می‌شوند.
  • Default Gateway برای رسیدن به Networkهای خارج از Subnet محلی اهمیت دارد.
  • DHCP می‌تواند IP و سایر تنظیمات Network را به صورت خودکار ارائه کند.
  • Routing Table مشخص می‌کند Packet از چه مسیر و Interfaceای ارسال شود.
  • Linux ابزارهای قدرتمندی مانند ip برای مشاهده و Troubleshooting Network دارد.
  • IP Address پایه بسیاری از مفاهیم Docker، Kubernetes، Cloud و Monitoring است.
🚀 نکته DevOps: اگر فقط یک چیز از این مقاله به خاطر می‌سپاری، این زنجیره را در ذهن داشته باش:

MAC ↓ ARP / Neighbor ↓ IP ↓ Subnet ↓ Gateway ↓ Route ↓ TCP / UDP ↓ Application

وقتی این رابطه را واقعاً بفهمی، مباحث بعدی مثل Subnetting، Routing، DNS، Firewall، Docker Networking و Kubernetes Networking خیلی منطقی‌تر خواهند شد.

  • Binary و تبدیل Decimal/Binary
