MAC Address چیست؟

MAC Address یا Media Access Control Address یک شناسه در سطح Data Link Layer است که برای شناسایی Interface شبکه در ارتباطات محلی Ethernet استفاده می‌شود.

اگر یک کامپیوتر را به Network وصل کنیم، Network Interface Card یا همان NIC باید یک شناسه داشته باشد تا Frameهای Ethernet بتوانند مقصد خود را مشخص کنند.

یک MAC Address معمولاً به شکل زیر نمایش داده می‌شود:

Example 
00:1A:2B:3C:4D:5E

این Address از 48 بیت تشکیل شده و معمولاً با 12 رقم Hexadecimal نمایش داده می‌شود.

💡 نکته مهم: MAC Address مربوط به ارتباط در شبکه محلی است. وقتی Packet از یک Router عبور می‌کند، MAC Address مربوط به Frame در هر Segment می‌تواند تغییر کند، در حالی که IP مقصد معمولاً همان مقصد منطقی باقی می‌ماند.

MAC در کدام Layer قرار دارد؟

برای درک MAC باید مدل OSI را بشناسیم.

Layer مثال نقش
Layer 7 HTTP Application
Layer 4 TCP / UDP Transport
Layer 3 IPv4 / IPv6 Routing و Logical Addressing
Layer 2 Ethernet / MAC Frame و ارتباط محلی
Layer 1 Cable / Fiber / Radio انتقال Physical Signal

پس:

MAC → Layer 2
IP → Layer 3
TCP/UDP → Layer 4

این تفکیک در Troubleshooting بسیار مهم است. اگر مشکل در MAC، VLAN یا Ethernet باشد، نباید مستقیماً دنبال DNS یا HTTP بگردیم.

ساختار MAC Address

یک MAC معمولی مانند: 

00:1A:2B:3C:4D:5E

از شش بخش دو رقمی تشکیل شده است. هر بخش یک Octet است.

در MAC Addressهای سنتی Ethernet، 48 بیت وجود دارد: 

48 bits

00000000 00011010 00101011 00111100 01001101 01011110

دو مفهوم مهم در بخش ابتدایی MAC عبارت‌اند از:

  • U/L bit برای مشخص‌کردن Local یا Universal بودن Address
  • I/G bit برای مشخص‌کردن Individual یا Group بودن Address

در محیط واقعی معمولاً لازم نیست این بیت‌ها را دستی محاسبه کنیم، اما دانستن مفهوم آن‌ها برای درک ساختار Ethernet مفید است.

Unicast، Multicast و Broadcast

همه MAC Addressها به یک شکل استفاده نمی‌شوند. یکی از دسته‌بندی‌های مهم، نوع مقصد Frame است.

Unicast

در Unicast، Frame برای یک مقصد مشخص ارسال می‌شود. مثلاً: 

Destination MAC:
00:1A:2B:3C:4D:5E

Broadcast

Broadcast یعنی Frame برای همه Hostهای موجود در Broadcast Domain ارسال شود. MAC مخصوص Broadcast: 

FF:FF:FF:FF:FF:FF

یکی از مثال‌های مهم استفاده از Broadcast، برخی فرآیندهای Discovery در شبکه محلی است.

Multicast

در Multicast، Frame برای یک گروه از Receiverها ارسال می‌شود. این مفهوم در بعضی پروتکل‌های Networking، Service Discovery و برخی سیستم‌های Distributed کاربرد دارد.

💡 در Troubleshooting شبکه، تشخیص اینکه Traffic به صورت Unicast، Broadcast یا Multicast است، می‌تواند در فهم رفتار Network بسیار کمک‌کننده باشد.

Switch چگونه MAC را یاد می‌گیرد؟

یکی از مهم‌ترین مفاهیم MAC Address، نحوه کار Ethernet Switch است.

Switch معمولاً یک MAC Address Table دارد. وقتی یک Ethernet Frame وارد Port می‌شود، Switch می‌تواند Source MAC را مشاهده کند و متوجه شود که آن MAC از کدام Port آمده است.

مثلاً فرض کنیم Switch چنین وضعیتی دارد:

MAC Port
00:11:22:33:44:55 Gi0/1
AA:BB:CC:DD:EE:FF Gi0/2

اگر Frameای برای AA:BB:CC:DD:EE:FF برسد، Switch می‌داند که باید آن را به Port مربوطه Forward کند.

اگر Destination MAC را در Table نداشته باشد، Switch ممکن است Frame را در Portهای مناسب Flood کند تا مقصد پیدا شود.

MAC Address Table

در Switchهای Managed معمولاً می‌توان MAC Address Table را مشاهده کرد. این Table برای Troubleshooting بسیار ارزشمند است.

برای مثال در تجهیزات Cisco معمولاً دستوری مشابه زیر وجود دارد:

Cisco IOS 
show mac address-table

از این اطلاعات می‌توانیم بفهمیم:

  • یک MAC از کدام Port دیده شده است.
  • آیا یک MAC روی چند Port دیده می‌شود یا نه.
  • آیا ممکن است Loop یا Misconfiguration داشته باشیم.
  • آیا Host موردنظر از مسیر مورد انتظار به Switch متصل است.
⚠️ دیدن یک MAC روی چند Port همیشه به معنی مشکل نیست. در محیط‌هایی مثل Virtualization، Trunk، Port-Channel و بعضی معماری‌های Network، رفتار طبیعی می‌تواند پیچیده‌تر باشد.

MAC Address در برابر IP Address

یکی از رایج‌ترین اشتباهات افراد تازه‌کار این است که MAC و IP را تقریباً یک مفهوم در نظر بگیرند. در حالی که این دو نقش متفاوتی دارند.

MAC IP
Layer 2 Layer 3
برای ارتباط محلی برای Logical Addressing
در Ethernet Frame در IP Packet
Switch بیشتر با آن کار می‌کند Router با آن Route می‌کند
معمولاً 48 بیت در Ethernet IPv4 برابر 32 بیت

یک مثال ساده: فرض کن کامپیوتر A می‌خواهد با Server B در همان شبکه محلی ارتباط برقرار کند. برای ارسال Ethernet Frame، کامپیوتر A باید MAC مقصد را بداند. اما اگر مقصد در یک Network دیگر باشد، Frame ابتدا به MAC مربوط به Next Hop / Default Gateway ارسال می‌شود.

💡 این نکته یکی از پایه‌های مهم Networking است: IP مشخص می‌کند Packet منطقی به کجا می‌رود، اما MAC مشخص می‌کند Frame فعلی در همین Segment به کدام Interface تحویل داده شود.

ARP چه ارتباطی با MAC دارد؟

اگر یک Host فقط IP مقصد را بداند، اما MAC آن را نداند، در شبکه IPv4 می‌تواند از ARP برای پیدا کردن MAC استفاده کند.

مثلاً فرض کنیم: 

Destination IP:
192.168.1.20

Destination MAC:
Unknown

Host می‌تواند یک ARP Request ارسال کند که مفهوم آن تقریباً این است:

«چه کسی IP آدرس 192.168.1.20 را دارد؟ MAC Address خودت را اعلام کن.»

Host مقصد پاسخ می‌دهد و MAC خود را اعلام می‌کند. در نتیجه Host فرستنده می‌تواند Mapping زیر را داشته باشد: 

192.168.1.20
        ↓
AA:BB:CC:DD:EE:FF

این اطلاعات معمولاً برای مدتی در ARP Cache نگهداری می‌شود.

مشاهده MAC Address در Linux

در Linux ابزار اصلی مدرن برای مشاهده Network Interfaceها، دستور ip است.

مشاهده همه Interfaceها

Ubuntu 
ip link

نمونه خروجی ممکن است چیزی شبیه این باشد: 

2: ens33: <BROADCAST,MULTICAST,UP,LOWER_UP>
    link/ether 00:0c:29:12:34:56

قسمت: 

link/ether 00:0c:29:12:34:56

MAC Address Interface را نشان می‌دهد.

مشاهده یک Interface مشخص 

ip link show ens33

مشاهده MAC با sysfs 

cat /sys/class/net/ens33/address

مشاهده اطلاعات کامل Interface 

ip addr show ens33

تغییر MAC Address در Linux

در بعضی محیط‌های Lab یا Virtualization ممکن است بخواهیم MAC Interface را موقتاً تغییر دهیم. ابتدا Interface را Down می‌کنیم: 

sudo ip link set dev ens33 down

سپس MAC جدید را تنظیم می‌کنیم: 

sudo ip link set dev ens33 address 02:11:22:33:44:55

و دوباره Interface را بالا می‌آوریم: 

sudo ip link set dev ens33 up

برای بررسی: 

ip link show ens33
⚠️ این کار را روی Interface اصلی سیستم Production بدون شناخت دقیق Network انجام نده. تغییر MAC می‌تواند باعث قطع ارتباط، مشکل DHCP، Port Security، Duplicate Address Detection یا مشکلات دیگر شود.

MAC در Virtual Machine و Docker

در محیط‌های مدرن DevOps فقط با Physical NIC سروکار نداریم. Virtualization باعث می‌شود Interfaceهای مجازی نیز داشته باشیم.

Virtual Machine

یک VM معمولاً یک Virtual NIC دارد که برای آن MAC Address تعریف می‌شود. مثلاً در VMware یا VirtualBox ممکن است چیزی شبیه این داشته باشیم: 

Virtual Machine
       |
       v
Virtual NIC
       |
       v
MAC Address
       |
       v
Virtual Switch

بنابراین وقتی روی Ubuntu داخل VM دستور زیر را اجرا می‌کنی: 

ip link
ممکن است MACای ببینی که متعلق به Virtual NIC ماشین باشد.

Docker

Containerها نیز Network Interface مجازی دارند. مثلاً در Docker معمولاً یک Interface مانند eth0 داخل Container وجود دارد. 

docker exec -it CONTAINER_ID ip link

این موضوع بعدها هنگام یادگیری Docker Networking بسیار مهم خواهد شد. Container فقط یک Process ساده نیست؛ در Network Namespace خودش Interface، IP و Route دارد.

💡 وقتی Docker را یاد بگیری، خواهی دید که مفاهیمی مثل MAC، IP، Network Namespace، Bridge، Veth Pair و NAT چگونه به یکدیگر متصل می‌شوند.

Troubleshooting با MAC Address

MAC Address در Troubleshooting چند کاربرد مهم دارد.

سناریو ۱: Interface بالا نیست 

ip link

به وضعیت‌هایی مثل UP و LOWER_UP توجه کن.

سناریو ۲: IP داریم اما Network کار نمی‌کند

ابتدا Interface و MAC را بررسی کن: 

ip link
ip addr
ip route

سپس Gateway را تست کن: 

ping -c 4 GATEWAY_IP

اگر Gateway قابل دسترسی نیست، قبل از بررسی DNS باید Layerهای پایین‌تر را بررسی کنیم.

سناریو ۳: بررسی ARP

برای مشاهده Neighbor Table: 

ip neigh

خروجی می‌تواند چیزی شبیه این باشد: 

192.168.1.1 dev ens33
lladdr 00:11:22:33:44:55
REACHABLE

اینجا می‌توانیم رابطه بین: 

IP
 ↓
MAC
 ↓
Interface

را مشاهده کنیم.

سناریو ۴: Duplicate یا MAC Conflict

در بعضی شبکه‌ها اگر دو Device با وضعیت نامناسب MAC یا تنظیمات Virtualization مشابه وارد Network شوند، ممکن است رفتارهای غیرعادی دیده شود. نشانه‌ها می‌توانند شامل:

  • قطع و وصل شدن ارتباط
  • جابجایی MAC بین Portهای Switch
  • رفتار غیرقابل پیش‌بینی Traffic
  • مشکل در Virtual Machineها

در این شرایط بررسی MAC Table روی Switch و بررسی Virtual NICها می‌تواند مفید باشد.

🧪 Lab عملی MAC Address

تمرین ۱ — پیدا کردن MAC سیستم

روی Ubuntu اجرا کن:

Ubuntu 
ip link

حالا Interface اصلی سیستم را پیدا کن و MAC آن را یادداشت کن.

تمرین ۲ — ارتباط IP و MAC

ابتدا IP و Route را ببین: 

ip addr
ip route

سپس Neighbor Table را بررسی کن: 

ip neigh

حالا سعی کن توضیح بدهی:

  • Gateway من چیست؟
  • MAC Gateway چیست؟
  • این MAC روی کدام Interface دیده می‌شود؟
  • وضعیت Neighbor چیست؟

تمرین ۳ — بررسی Network

ip link
ip addr
ip route
ip neigh
ping -c 4 1.1.1.1

برای هر Command توضیح بده که مربوط به کدام Layer یا بخش Network است.

کاربرد MAC Address در DevOps

شاید در نگاه اول MAC Address یک موضوع صرفاً Network باشد، اما در کار واقعی DevOps بارها با آن مواجه خواهی شد.

Virtualization

در VMware، VirtualBox، Hyper-V و سایر Hypervisorها، Virtual NICها MAC Address دارند.

Docker Networking

Docker Containerها Network Interface مجازی دارند و در شبکه‌های Bridge، ارتباط بین Containerها و Host به مفاهیمی مثل Ethernet، MAC و Virtual Interface وابسته است.

Kubernetes

در Kubernetes نیز Network از Interfaceها و Network Namespaceهای مختلف تشکیل می‌شود. وقتی وارد مباحث CNI و Container Networking شوی، درک Layer 2 و Layer 3 بسیار مهم خواهد بود.

Monitoring

در بعضی محیط‌های Monitoring و Asset Management، MAC Address می‌تواند به‌عنوان یکی از مشخصه‌های شناسایی Interface یا Device استفاده شود.

Troubleshooting

وقتی یک Server، VM، Container یا Network Device رفتار غیرعادی دارد، دانستن رابطه: 

Device
   ↓
Interface
   ↓
MAC
   ↓
IP
   ↓
Route
   ↓
Application

باعث می‌شود Troubleshooting را به‌صورت منطقی و Layer-by-Layer انجام دهی.

🎯 چه چیزی یاد گرفتیم؟

  • MAC Address یک شناسه مهم در Layer 2 و Ethernet است.
  • MAC و IP دو مفهوم متفاوت با نقش‌های متفاوت هستند.
  • Switchها از MAC Address Table برای Forward کردن Frameها استفاده می‌کنند.
  • ARP در IPv4 برای پیدا کردن MAC متناظر با IP در شبکه محلی کاربرد دارد.
  • در Linux می‌توان با ip link و ip neigh اطلاعات MAC را بررسی کرد.
  • Virtual Machineها و Containerها نیز می‌توانند Interfaceهای شبکه و MAC داشته باشند.
  • MAC Address یکی از مفاهیم پایه برای درک Docker Networking و Kubernetes Networking است.
  • در Troubleshooting بهتر است از Layerهای پایین‌تر شروع کنیم و مرحله‌به‌مرحله به Application برسیم.
🚀 نکته مهم برای مسیر DevOps: MAC Address را فقط به‌عنوان یک شماره حفظ نکن. سعی کن همیشه این زنجیره را در ذهن داشته باشی:

Physical / Virtual Interface ↓ MAC ↓ ARP / Neighbor ↓ IP ↓ Route ↓ TCP / UDP ↓ Application

وقتی این مدل ذهنی را داشته باشی، Troubleshooting شبکه در Linux، Docker، Kubernetes، Cloud و Infrastructure بسیار قابل‌فهم‌تر می‌شود.
