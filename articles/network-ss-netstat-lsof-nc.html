چرا این ابزارها مهم هستند؟

در Troubleshooting شبکه فقط دانستن IP کافی نیست. باید بتوانیم بفهمیم:

  • چه Portهایی Listening هستند؟
  • چه Connectionهایی برقرارند؟
  • کدام Process از یک Port استفاده می‌کند؟
  • آیا Port مقصد قابل دسترسی است؟

ss

ss یکی از ابزارهای اصلی Linux برای مشاهده Socketها و Connectionهای شبکه است.

Terminal
ss

ss -t

ss -u

ss -l

ss -n

ss -tuln
Option Meaning
-t TCP
-u UDP
-l Listening
-n نمایش عددی Address و Port
-p نمایش Process

netstat

netstat ابزار قدیمی‌تر برای مشاهده Network Connectionها است و در بسیاری از سیستم‌های جدید دیگر ابزار اصلی محسوب نمی‌شود.

Terminal
netstat -tuln

netstat -tulpn
💡 در Linuxهای جدید معمولاً بهتر است برای کارهای روزمره Network از ss استفاده کنی، اما دانستن netstat برای Troubleshooting سیستم‌های قدیمی مفید است.

lsof

lsof برای پیدا کردن فایل‌ها و Resourceهای باز توسط Processها استفاده می‌شود و می‌تواند Socketهای شبکه را نیز نشان دهد.

Terminal
sudo lsof -i

sudo lsof -i :22

sudo lsof -i :8080

nc / Netcat

Netcat یا nc یکی از ابزارهای ساده و بسیار کاربردی برای تست Connectionهای شبکه است.

برای مثال:

Terminal
nc -vz 192.168.1.10 22

اگر Port قابل دسترسی باشد معمولاً خروجی موفقیت‌آمیز دریافت می‌کنی.

تست یک Web Server

Terminal
nc -vz example.com 443

مقایسه ابزارها

Tool بهترین کاربرد
ss Socket و Connection
netstat سیستم‌های قدیمی و آشنایی با ابزار Legacy
lsof پیدا کردن Process مربوط به Port
nc تست Connection به مقصد

سناریوهای واقعی

سناریو 1 — آیا Port باز است؟

Terminal
nc -vz 10.10.10.20 443

سناریو 2 — چه چیزی روی Port 8080 است؟

Terminal
sudo lsof -i :8080

سناریو 3 — چه Portهایی Listening هستند؟

Terminal
sudo ss -tulnp

سناریو 4 — چه Connectionهایی برقرار هستند؟

Terminal
ss -tun

کاربرد در DevOps

این ابزارها در سناریوهای واقعی DevOps بسیار پرکاربرد هستند:

  • بررسی Web Server
  • بررسی Database Connection
  • Troubleshooting Docker
  • بررسی Kubernetes Node
  • Monitoring
  • SSH Troubleshooting
  • Firewall Troubleshooting
  • Load Balancer Troubleshooting
⚠️ اگر یک Port Listening نیست، قبل از تغییر Firewall یا Network Configuration ابتدا بررسی کن که خود Service اجرا شده باشد.

تمرین عملی

🧪 Network Tools Lab

این دستورات را روی Ubuntu اجرا کن:

Terminal
ss -tulnp

ss -tun

sudo lsof -i

sudo lsof -i :22

nc -vz localhost 22

برای هر خروجی مشخص کن:

  • Local Address چیست؟
  • Port چیست؟
  • Protocol چیست؟
  • Process مربوطه چیست؟
  • Connection در چه Stateای قرار دارد؟

Network Tools Cheat Sheet

Command کاربرد
ss -tuln Listening TCP/UDP
ss -tulnp Listening + Process
ss -tun TCP/UDP Connections
netstat -tuln Network Connections در سیستم‌های Legacy
lsof -i Network Files/Sockets
lsof -i :22 Process مربوط به Port 22
nc -vz host port تست TCP Connection

چیزی که از این مرحله یاد گرفتم

  • ss ابزار اصلی من برای بررسی Socket و Connection است.
  • lsof برای پیدا کردن Process مربوط به Port بسیار مفید است.
  • nc برای تست دسترسی به Port کاربرد دارد.
  • netstat بیشتر برای سیستم‌های قدیمی و Legacy مهم است.
  • در Troubleshooting بهتر است مرحله‌به‌مرحله جلو برویم و بدون دلیل Configuration را تغییر ندهیم.

مرحله بعدی چیست؟

🚦 Routing

حالا که IP، Subnet، Port و Connection را شناختیم، مرحله بعدی Routing است. در بخش بعدی بررسی می‌کنیم Packet چگونه مسیر خود را از Source به Destination پیدا می‌کند و Default Gateway و Routing Table چه نقشی دارند.
