مدل OSI چیست؟

OSI مخفف Open Systems Interconnection است.

مدل OSI یک مدل مفهومی برای توضیح نحوه ارتباط سیستم‌های مختلف در شبکه است. این مدل ارتباطات شبکه را به هفت لایه تقسیم می‌کند تا بتوانیم وظایف مختلف شبکه را از یکدیگر جدا کنیم.

برای یک DevOps Engineer دانستن OSI صرفاً برای امتحان یا حفظ کردن هفت لایه نیست. وقتی یک سرویس در دسترس نیست، DNS کار نمی‌کند، یک Port بسته است یا ارتباط بین دو Server قطع شده، مدل OSI به ما کمک می‌کند مشکل را مرحله‌به‌مرحله پیدا کنیم.

Layer 1 — Physical

لایه Physical پایین‌ترین لایه OSI است. این لایه با انتقال واقعی Bitها روی محیط فیزیکی سروکار دارد.

مواردی مثل کابل Ethernet، فیبر نوری، سیگنال الکتریکی، سیگنال نوری و تجهیزات فیزیکی در این سطح قرار می‌گیرند.

در محیط Server اگر Cable قطع باشد یا Interface فیزیکی Link نداشته باشد، مشکل می‌تواند از Layer 1 شروع شده باشد.

Layer 2 — Data Link

در Layer 2 داده‌ها در قالب Frame منتقل می‌شوند. یکی از مفاهیم بسیار مهم این لایه MAC Address است.

Switchها عمدتاً در این لایه کار می‌کنند و برای Forward کردن Frameها از MAC Address استفاده می‌کنند.

Layer 3 — Network

Layer 3 مربوط به Addressing و Routing است. مهم‌ترین مفهوم این لایه IP Address است.

Routerها با استفاده از Routing Table تصمیم می‌گیرند Packet باید از چه مسیری ارسال شود.

Terminal
ip addr
ip route

Layer 4 — Transport

در Layer 4 پروتکل‌هایی مثل TCP و UDP قرار دارند.

TCP ارتباط Connection-oriented ایجاد می‌کند و قابلیت‌هایی مانند Reliability و Ordering دارد. UDP سبک‌تر است و Connection ایجاد نمی‌کند.

Portها نیز در این لایه اهمیت زیادی دارند. مثلاً SSH معمولاً روی TCP Port 22 کار می‌کند.

Layer 5 — Session

Session Layer مسئول ایجاد، مدیریت و پایان دادن به Sessionهای ارتباطی است. در معماری‌های مدرن بسیاری از وظایف این لایه با لایه‌های دیگر ترکیب شده‌اند.

Layer 6 — Presentation

این لایه با نحوه نمایش و تبدیل داده‌ها سروکار دارد. Encoding، Compression و Encryption از مفاهیمی هستند که معمولاً با این لایه مرتبط می‌شوند.

Layer 7 — Application

Application Layer نزدیک‌ترین لایه به برنامه‌های کاربردی است.

پروتکل‌هایی مثل HTTP، HTTPS، DNS و SSH در این سطح مورد بررسی قرار می‌گیرند.

Encapsulation چیست؟

هنگامی که یک Application داده‌ای را ارسال می‌کند، داده در مسیر عبور از لایه‌ها Headerهای مختلفی دریافت می‌کند. به این فرآیند Encapsulation گفته می‌شود.

OSI در Troubleshooting

یکی از کاربردهای مهم OSI برای DevOps، Troubleshooting است.

فرض کنیم یک Web Application باز نمی‌شود. می‌توانیم از پایین به بالا بررسی کنیم:

💡 قرار نیست در هر مشکل شبکه دقیقاً هفت مرحله را بررسی کنیم. هدف OSI ایجاد یک Mental Model است تا بدانیم مشکل احتمالاً در کدام بخش قرار دارد.

چیزی که از این مرحله یاد گرفتم

  • مدل OSI یک نقشه ذهنی برای فهم شبکه است.
  • هفت لایه از Physical تا Application وظایف شبکه را از هم جدا می‌کنند.
  • Encapsulation یعنی افزوده شدن Headerهای مختلف در مسیر عبور داده از لایه‌ها.
  • برای DevOps مهم‌ترین بخش این است که بتوانم ارتباط بین Application، TCP، Port، IP، Routing و Network Interface را درک کنم.
  • OSI می‌تواند به‌عنوان یک چک‌لیست ذهنی برای Troubleshooting شبکه از پایین به بالا استفاده شود.
