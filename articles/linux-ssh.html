Linux SSH

آشنایی با SSH و نحوه اتصال امن به سرورهای لینوکسی

یکی از اولین چیزهایی که هنگام کار با سرورهای لینوکسی باید یاد بگیریم، نحوه اتصال به سرور است.

در محیط‌های واقعی DevOps معمولاً سرورها در یک دیتاسنتر، Cloud یا Virtual Machine قرار دارند و ما مستقیماً پشت سیستم آن‌ها نیستیم.

بنابراین باید بتوانیم از طریق شبکه به سرور متصل شویم، دستورات خود را اجرا کنیم، سرویس‌ها را بررسی کنیم، لاگ‌ها را ببینیم و در صورت نیاز تنظیمات سرور را تغییر دهیم.

یکی از مهم‌ترین ابزارهایی که برای این کار استفاده می‌شود SSH است.

SSH چیست؟

SSH مخفف Secure Shell است.

SSH یک پروتکل شبکه برای برقراری ارتباط امن با سیستم‌های دیگر است.

در دنیای Linux و DevOps، SSH بیشتر برای اتصال به سرورها و مدیریت آن‌ها استفاده می‌شود.

یکی از ویژگی‌های مهم SSH این است که اطلاعات ارتباطی به صورت رمزنگاری‌شده منتقل می‌شوند.

💡 نکته:

SSH فقط برای ورود به سرور نیست. از آن می‌توان برای انتقال فایل، اجرای دستورات از راه دور و ایجاد ارتباط امن بین سیستم‌ها نیز استفاده کرد.

چرا SSH برای DevOps مهم است؟

تقریباً در تمام محیط‌های Linux Server با SSH مواجه خواهیم شد.

برای مثال فرض کنید یک سرور Ubuntu داریم: 

192.168.1.100

و روی آن سرویس‌هایی مانند Nginx، Docker یا Zabbix اجرا می‌شوند.

به جای اینکه مستقیماً به سرور دسترسی فیزیکی داشته باشیم، می‌توانیم از سیستم خودمان با SSH به آن متصل شویم.

بنابراین SSH یکی از ابزارهای پایه برای:

  • مدیریت Linux Server
  • مدیریت Cloud Server
  • کار با Virtual Machine
  • Deploy کردن برنامه‌ها
  • بررسی Logها
  • عیب‌یابی سرویس‌ها
  • مدیریت Docker
  • اتوماسیون DevOps

SSH Client و SSH Server

برای برقراری ارتباط SSH معمولاً دو طرف داریم:

SSH Client

سیستمی است که از آن برای اتصال استفاده می‌کنیم.

برای مثال لپ‌تاپ یا کامپیوتر ما می‌تواند SSH Client باشد.

SSH Server

سیستمی است که می‌خواهیم به آن متصل شویم.

در Ubuntu معمولاً سرویس SSH توسط OpenSSH Server ارائه می‌شود.

اتصال به سرور با SSH

ساده‌ترین شکل دستور SSH به صورت زیر است: 

ssh username@server-ip

برای مثال: 

ssh admin@192.168.1.100

در این دستور:

  • ssh نام دستور است.
  • admin نام کاربر روی سرور است.
  • 192.168.1.100 آدرس IP سرور است.

بعد از اجرای دستور، اگر احراز هویت با Password باشد، سیستم از ما رمز عبور کاربر را درخواست می‌کند.

⚠️ توجه:

هنگام وارد کردن Password در SSH معمولاً چیزی روی صفحه نمایش داده نمی‌شود؛ حتی ستاره هم نشان داده نمی‌شود. این رفتار طبیعی است.

اتصال به پورت مشخص

پورت پیش‌فرض SSH معمولاً: 

22

است.

اگر SSH روی پورت دیگری تنظیم شده باشد، می‌توانیم پورت را هنگام اتصال مشخص کنیم. 

ssh -p 2222 admin@192.168.1.100

در اینجا SSH به جای پورت 22 از پورت 2222 استفاده می‌کند.

SSH Key چیست؟

یکی از روش‌های امن‌تر برای احراز هویت در SSH، استفاده از SSH Key است.

در روش Key-based Authentication معمولاً دو کلید داریم:

  • Private Key
  • Public Key

Private Key باید روی سیستم خودمان باقی بماند و نباید آن را در اختیار افراد دیگر قرار دهیم.

Public Key را می‌توان روی سرور قرار داد.

🔐 قانون مهم:

Private Key را مثل Password در نظر بگیر. آن را برای کسی ارسال نکن و داخل Git Repository عمومی قرار نده.

ساخت SSH Key

برای ساخت یک SSH Key می‌توانیم از دستور زیر استفاده کنیم: 

ssh-keygen -t ed25519

سیستم از ما محل ذخیره کلید و در صورت تمایل Passphrase را می‌پرسد.

معمولاً کلیدها در مسیر زیر قرار می‌گیرند: 

~/.ssh/

بعد از ساخت Key ممکن است فایل‌هایی شبیه این داشته باشیم: 

id_ed25519
id_ed25519.pub

فایل: 

id_ed25519

کلید خصوصی است.

و: 

id_ed25519.pub

کلید عمومی است.

authorized_keys چیست؟

در سمت سرور، Public Keyهای مجاز معمولاً در فایل: 

~/.ssh/authorized_keys

ذخیره می‌شوند.

اگر Public Key ما در این فایل قرار گرفته باشد، در صورت درست بودن تنظیمات SSH می‌توانیم بدون وارد کردن Password به سرور متصل شویم.

استفاده از ssh-copy-id

یکی از روش‌های ساده برای کپی کردن Public Key روی سرور استفاده از دستور زیر است: 

ssh-copy-id username@server-ip

برای مثال: 

ssh-copy-id admin@192.168.1.100

Permissionهای مهم

Permissionهای نادرست در پوشه SSH می‌توانند باعث مشکل در احراز هویت شوند. 

chmod 700 ~/.ssh
chmod 600 ~/.ssh/authorized_keys

فایل SSH Config

اگر دائماً به چند سرور متصل شویم، نوشتن کامل دستور SSH هر بار می‌تواند خسته‌کننده باشد.

برای حل این مشکل می‌توانیم از فایل: 

~/.ssh/config

استفاده کنیم.

برای مثال: 

Host myserver
    HostName 192.168.1.100
    User admin
    Port 22

حالا به جای: 

ssh admin@192.168.1.100

می‌توانیم فقط بنویسیم: 

ssh myserver
💡 نکته:

فایل SSH Config مخصوصاً زمانی که با تعداد زیادی Server کار می‌کنیم بسیار کاربردی است.

انتقال فایل با SSH

SSH فقط برای اجرای دستورات نیست.

یکی از ابزارهایی که از SSH استفاده می‌کند SCP است.

ارسال فایل به سرور 

scp backup.tar.gz admin@192.168.1.100:/home/admin/

دریافت فایل از سرور 

scp admin@192.168.1.100:/home/admin/backup.tar.gz .

نقطه در انتهای دستور به معنی Current Directory است.

عیب‌یابی اتصال SSH

گاهی SSH کار نمی‌کند و باید مرحله‌به‌مرحله مشکل را پیدا کنیم.

1. بررسی دسترسی شبکه 

ping 192.168.1.100

این دستور فقط دسترسی ICMP را بررسی می‌کند و به‌تنهایی نشان نمی‌دهد که پورت SSH باز است.

2. بررسی پورت SSH

اگر ابزار netcat نصب باشد: 

nc -zv 192.168.1.100 22

3. اجرای SSH در حالت Debug

یکی از بهترین ابزارها برای پیدا کردن مشکل SSH: 

ssh -v admin@192.168.1.100

در صورت نیاز می‌توان از Debug بیشتر نیز استفاده کرد: 

ssh -vv admin@192.168.1.100

و: 

ssh -vvv admin@192.168.1.100

4. بررسی وضعیت SSH Server

روی Ubuntu می‌توان وضعیت سرویس SSH را بررسی کرد: 

sudo systemctl status ssh

اگر سرویس اجرا نشده باشد، می‌توان آن را بررسی یا Start کرد: 

sudo systemctl start ssh

5. بررسی Logهای SSH

برای دیدن Logهای مربوط به سرویس SSH: 

sudo journalctl -u ssh

برای دیدن آخرین Logها: 

sudo journalctl -u ssh -n 50

نکات امنیتی SSH

SSH یکی از نقاط مهم امنیتی یک Linux Server است. بنابراین باید تنظیمات آن را با دقت انجام دهیم.

استفاده از SSH Key

در محیط‌های عملی بهتر است به جای تکیه صرف بر Password، از SSH Key و سیاست احراز هویت مناسب استفاده شود.

استفاده از Password قوی

اگر Password Authentication فعال است، استفاده از Password ضعیف می‌تواند ریسک حملات Brute Force را افزایش دهد.

محدود کردن دسترسی شبکه

بهتر است دسترسی SSH فقط از شبکه‌ها یا IPهایی که واقعاً نیاز دارند امکان‌پذیر باشد.

تغییر Port چه نقشی دارد؟

تغییر پورت SSH ممکن است تعداد برخی اسکن‌های خودکار را کاهش دهد، اما به‌تنهایی یک راهکار امنیتی اصلی محسوب نمی‌شود.

امنیت واقعی باید با روش‌هایی مانند Authentication مناسب، Firewall، محدودسازی دسترسی و Monitoring انجام شود.

🧪 تمرین عملی

حالا یک تمرین ساده انجام دهیم.

فرض کنیم یک Ubuntu Server با IP زیر داریم: 

192.168.1.100

ابتدا به آن متصل شو: 

ssh admin@192.168.1.100

بعد از ورود، اطلاعات سیستم را بررسی کن: 

hostname
whoami
uptime
df -h

سپس وضعیت SSH را بررسی کن: 

sudo systemctl status ssh

در مرحله بعد Logهای SSH را ببین: 

sudo journalctl -u ssh -n 30

SSH در دنیای DevOps

SSH یکی از ابزارهای پایه‌ای است که تقریباً در تمام مسیر یادگیری DevOps با آن برخورد خواهیم داشت.

برای مثال هنگام کار با:

  • Linux Server
  • Docker
  • Kubernetes
  • Ansible
  • CI/CD
  • Cloud
  • Monitoring
  • Virtual Machines

در بسیاری از سناریوها SSH نقش مهمی در مدیریت و دسترسی به سیستم‌ها دارد.

📌 Cheat Sheet

دستور کاربرد
ssh user@host اتصال به سرور
ssh -p 2222 user@host اتصال به پورت مشخص
ssh-keygen -t ed25519 ساخت SSH Key
ssh-copy-id user@host کپی Public Key
ssh -v user@host Debug اتصال
scp file user@host:/path ارسال فایل
systemctl status ssh بررسی وضعیت SSH
journalctl -u ssh مشاهده Logهای SSH
