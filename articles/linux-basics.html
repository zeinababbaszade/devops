چرا Linux؟

وقتی تصمیم گرفتم مسیر یادگیری DevOps را شروع کنم، یکی از اولین چیزهایی که متوجه شدم این بود که باید با Linux راحت باشم.

بسیاری از سرورها و محیط‌های زیرساختی مورد استفاده در دنیای DevOps بر پایه Linux هستند و ابزارهایی مثل Docker، Kubernetes، سیستم‌های مانیتورینگ و بسیاری از سرویس‌های Cloud را در عمل زیاد در محیط Linux خواهیم دید.

💡 هدف این مقاله: قرار نیست در یک مقاله Linux را کامل یاد بگیرم. هدف من این است که از پایه با Terminal و فایل‌سیستم Linux کار کنم و هر مرحله را واقعاً روی Ubuntu اجرا و تست کنم.

Terminal چیست؟

Terminal یک رابط متنی برای کار با سیستم است. در آن به جای استفاده از رابط گرافیکی، دستورات را وارد می‌کنیم و سیستم نتیجه را برمی‌گرداند.

در مسیر DevOps استفاده از Terminal بسیار مهم است، چون بخش بزرگی از کارهای مربوط به سرورها، سرویس‌ها، فایل‌ها، شبکه و Automation از طریق Command Line انجام می‌شود.

یک نکته مهم این است که Terminal، Shell و Command Line دقیقاً مترادف یکدیگر نیستند؛ اما در شروع مسیر لازم نیست درگیر این تفاوت‌ها شویم.

اولین سؤال: الان کجا هستم؟

وقتی Terminal را باز می‌کنیم، Shell یک Working Directory دارد؛ یعنی مسیری که در حال حاضر در آن قرار داریم.

برای فهمیدن مسیر فعلی از دستور pwd استفاده می‌کنیم.

Terminal 
pwd

خروجی معمولاً چیزی شبیه این است:

Output 
/home/username

دستور pwd مخفف Print Working Directory است. مستندات Ubuntu نیز از آن برای نمایش مسیر فعلی استفاده می‌کند. :contentReference[oaicite:1]{index=1}

چه فایل‌هایی اینجا وجود دارند؟

برای مشاهده فایل‌ها و Directoryهای موجود در مسیر فعلی از دستور ls استفاده می‌کنیم.

Terminal 
ls

برای دیدن اطلاعات بیشتر می‌توانیم از گزینه -l استفاده کنیم: 

ls -l

و اگر بخواهیم فایل‌های مخفی را هم ببینیم: 

ls -a

ترکیب این دو گزینه نیز بسیار پرکاربرد است: 

ls -la
💡 در Linux فایل‌ها و Directoryهایی که نامشان با . شروع می‌شود معمولاً در خروجی عادی ls نمایش داده نمی‌شوند و برای دیدن آن‌ها می‌توان از ls -a استفاده کرد.

حرکت بین Directoryها

برای تغییر Directory از دستور cd استفاده می‌کنیم.

رفتن به یک مسیر 

cd /tmp

برگشتن به Home 

cd ~

علامت ~ یک میانبر برای Home Directory کاربر فعلی است. :contentReference[oaicite:2]{index=2}

رفتن یک مرحله به عقب 

cd ..

برگشتن به مسیر قبلی 

cd -

رفتن به Root 

cd /
⚠️ توجه: در Linux دو مفهوم با نام root داریم. / به Root Directory سیستم اشاره دارد، در حالی که root نام کاربر Superuser نیز هست. این دو مفهوم را با هم اشتباه نگیریم.

من با چه کاربری وارد شده‌ام؟

برای فهمیدن نام کاربری فعلی می‌توانیم از whoami استفاده کنیم. 

whoami

این دستور مخصوصاً زمانی مفید است که روی یک سرور کار می‌کنیم و مطمئن نیستیم با چه Userای وارد شده‌ایم.

نام سیستم چیست؟

دستور hostname نام سیستم را نمایش می‌دهد. 

hostname

ساخت Directory

برای ساخت یک Directory جدید از دستور mkdir استفاده می‌کنیم. 

mkdir devops-lab

حالا وارد آن می‌شویم: 

cd devops-lab

و با pwd بررسی می‌کنیم که واقعاً وارد مسیر موردنظر شده‌ایم. 

pwd

mkdir مخفف Make Directory است. :contentReference[oaicite:3]{index=3}

ساخت فایل

دستور touch می‌تواند یک فایل خالی ایجاد کند. 

touch notes.txt

حالا با ls می‌توانیم فایل را ببینیم: 

ls -l

در این مرحله یک فایل به نام notes.txt داریم.

مشاهده محتوای فایل

برای مشاهده محتوای یک فایل متنی می‌توانیم از cat استفاده کنیم. 

cat notes.txt

چون فایل تازه ساخته شده و خالی است، احتمالاً خروجی خاصی نمی‌بینیم.

نوشتن داخل فایل با echo

دستور echo می‌تواند یک متن را در Terminal نمایش دهد. 

echo "Hello Linux"

اما می‌توانیم خروجی آن را به یک فایل هم بفرستیم: 

echo "My first Linux note" > notes.txt

حالا محتوای فایل را بررسی می‌کنیم: 

cat notes.txt

خروجی: 

My first Linux note

تفاوت > و >>

این یکی از مفاهیم مهمی است که از همین ابتدا باید به آن توجه کنیم.

علامت >

علامت > خروجی را در فایل می‌نویسد و اگر فایل قبلاً محتوا داشته باشد، محتوای قبلی جایگزین می‌شود. 

echo "Line 1" > notes.txt

علامت >>

علامت >> متن جدید را به انتهای فایل اضافه می‌کند. 

echo "Line 2" >> notes.txt

حالا: 

cat notes.txt

خروجی: 

Line 1
Line 2
⚠️ هنگام استفاده از > مراقب باش. اگر فایل مهمی را به اشتباه با این عملگر بازنویسی کنی، ممکن است محتوای قبلی آن از بین برود.

تمرین عملی: ساخت DevOps Lab

حالا می‌خواهم یک محیط کوچک برای تمرین‌های آینده DevOps خودم بسازم.

🧪 تمرین

دستورات زیر را در Ubuntu اجرا کن و خروجی هر مرحله را بررسی کن.

Ubuntu Terminal 
mkdir ~/devops-lab

cd ~/devops-lab

mkdir linux
mkdir docker
mkdir networking

touch linux/commands.txt
touch linux/notes.txt

echo "My Linux Learning Journey" > linux/notes.txt

echo "Linux is the foundation of my DevOps journey" >> linux/notes.txt

ls -la

ls -la linux

cat linux/notes.txt

اگر همه چیز درست انجام شده باشد، ساختار ساده‌ای شبیه این خواهیم داشت: 

devops-lab/
├── linux/
│   ├── commands.txt
│   └── notes.txt
├── docker/
└── networking/

Linux Command Cheat Sheet

تا اینجا این دستورات را یاد گرفتیم:

Command کاربرد
pwd نمایش مسیر فعلی
ls نمایش فایل‌ها و Directoryها
ls -la نمایش جزئیات و فایل‌های مخفی
cd تغییر Directory
cd .. رفتن به Parent Directory
cd ~ رفتن به Home
cd - برگشت به مسیر قبلی
whoami نمایش User فعلی
hostname نمایش نام سیستم
mkdir ساخت Directory
touch ساخت فایل خالی
cat نمایش محتوای فایل
echo نمایش یا نوشتن متن

چیزی که از این مرحله یاد گرفتم

  • Terminal محیط اصلی کار با Linux از طریق Command Line است.
  • با pwd می‌توانم بفهمم در کدام Directory هستم.
  • با ls محتویات یک Directory را مشاهده می‌کنم.
  • با cd بین Directoryها جابه‌جا می‌شوم.
  • ~ به Home Directory اشاره می‌کند.
  • .. به Parent Directory اشاره دارد.
  • با mkdir Directory می‌سازم.
  • با touch فایل ایجاد می‌کنم.
  • با cat محتوای فایل را می‌بینم.
  • با > خروجی را بازنویسی و با >> به انتهای فایل اضافه می‌کنم.

مرحله بعدی چیست؟

در مقاله بعدی وارد یکی از مهم‌ترین مباحث Linux می‌شوم:

🐧 Linux File System

در مرحله بعد با ساختار فایل‌سیستم Linux آشنا می‌شوم و بررسی می‌کنم که Directoryهای مهمی مثل این‌ها چه کاربردی دارند:

  • /
  • /home
  • /etc
  • /var
  • /tmp
  • /usr
  • /opt
🚀 این فقط شروع مسیر است. هدف این سایت ثبت چیزهایی است که واقعاً یاد می‌گیرم، روی سیستمم تست می‌کنم و در پروژه‌های واقعی به کار می‌برم.
