Regex چیست؟

Regex Basics فقط یک دستور یا مفهوم حفظی نیست؛ در کار واقعی DevOps باید بتوانی آن را مشاهده کنی، نتیجه را تفسیر کنی، اثر تغییر را بسنجی و در صورت خطا به وضعیت قبلی برگردی.

در Linux تقریباً همیشه بهتر است قبل از تغییر، وضعیت فعلی را ثبت کنیم. این کار باعث می‌شود بین «چیزی که واقعاً خراب است» و «چیزی که فکر می‌کنیم خراب است» تفاوت بگذاریم. در محیط Production، همین عادت ساده از تغییرات تصادفی و تشخیص اشتباه جلوگیری می‌کند.

برای این بخش، ابتدا هدف را مشخص کن: چه چیزی را می‌خواهیم بفهمیم، چه خروجی‌ای باید ببینیم و چه نشانه‌ای مشخص می‌کند که وضعیت سالم است؟ این سه سؤال، پایه Troubleshooting حرفه‌ای هستند.

Ubuntu / Bash
grep -E '^ERROR' app.log 2>/dev/null
grep -E 'timeout|failed|refused' app.log 2>/dev/null

درک ارتباط بین مفاهیم مهم‌تر از حفظ کردن گزینه‌های Command است. برای مثال یک Service می‌تواند Process داشته باشد، روی یک Port گوش دهد، Log تولید کند و از Permission و Network استفاده کند؛ بنابراین یک مشکل ظاهراً ساده ممکن است چند لایه داشته باشد.

Ubuntu / Bash
grep -E '^[0-9]{1,3}(\.[0-9]{1,3}){3}$' ips.txt 2>/dev/null
💡 نکته DevOps: خروجی ابزارها بخشی از Evidence هستند. در Incident، Timestamp و Commandی که اجرا کرده‌ای را ثبت کن تا بعداً بتوانی تصمیم خودت را توضیح بدهی.

Ubuntu / Bash
grep -E '^[[:space:]]*#|^[[:space:]]*$' config.conf 2>/dev/null

خطاهای رایج معمولاً از سه دسته می‌آیند: Configuration اشتباه، Permission یا Dependency، و Resource/Connectivity. به‌جای حدس زدن، هر فرضیه را با یک تست کوچک و قابل بازگشت بررسی کن.

Ubuntu / Bash
grep -E '^ERROR' app.log 2>/dev/null
grep -E 'timeout|failed|refused' app.log 2>/dev/null
⚠️ هشدار: دستورهای دارای sudo یا تغییر فایل‌های سیستمی را کورکورانه کپی نکن. ابتدا روی VM آزمایش کن و قبل از Restart یا حذف، Configuration را Validate کن.

🧪 سناریوی تمرینی

در Ubuntu آزمایشگاهی یک سناریو برای همین موضوع بساز. ابتدا وضعیت فعلی را ثبت کن، سپس یک تغییر کوچک ایجاد کن و در نهایت با ابزارهای مشاهده و Logها نتیجه را Verify کن.

  1. اطلاعات سیستم و وضعیت فعلی را ثبت کن.
  2. دستورهای مقاله را بدون تغییر روی محیط آزمایشگاهی اجرا کن.
  3. حداقل یک خروجی را تفسیر کن و دلیل نتیجه را با زبان خودت بنویس.
  4. اگر تغییری ایجاد کردی، آن را به حالت قبلی برگردان.
  5. یک Incident Note کوتاه شامل Symptom، Evidence، Root Cause و Fix بنویس.

چیزی که یاد گرفتم
