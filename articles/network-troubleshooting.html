Network Troubleshooting چیست؟

Network Troubleshooting یعنی پیدا کردن علت یک مشکل ارتباطی در شبکه و برطرف کردن آن.

مثلاً ممکن است یک Server به اینترنت دسترسی نداشته باشد، یک Client نتواند به Server وصل شود، یک Website باز نشود یا یک Application نتواند با Database ارتباط برقرار کند.

در محیط‌های DevOps، توانایی Troubleshooting شبکه بسیار مهم است؛ چون بسیاری از خطاهایی که در ظاهر مربوط به Application هستند، در واقع از Network، DNS، Firewall، Routing یا Portها ناشی می‌شوند.

💡 هدف Troubleshooting این نیست که فقط چند Command اجرا کنیم؛ باید بتوانیم مشکل را مرحله‌به‌مرحله محدود کنیم و بفهمیم دقیقاً در کدام بخش ارتباط اختلال وجود دارد.

روش اصولی عیب‌یابی شبکه

یکی از مهم‌ترین مهارت‌ها در Troubleshooting این است که از پایین‌ترین لایه‌های ارتباط شروع کنیم و مرحله‌به‌مرحله جلو برویم.

یک مسیر ساده می‌تواند این باشد:

  1. آیا Network Interface فعال است؟
  2. آیا سیستم IP دارد؟
  3. آیا Gateway قابل دسترسی است؟
  4. آیا IP مقصد قابل دسترسی است؟
  5. آیا DNS درست کار می‌کند؟
  6. آیا Port سرویس باز است؟
  7. آیا خود Application پاسخ می‌دهد؟
💡 اگر از همان ابتدا سراغ Application برویم، ممکن است زمان زیادی را صرف بررسی چیزی کنیم که مشکل اصلی آن در Network یا DNS است.

بررسی Network Interface با ip

اولین چیزی که باید بررسی کنیم وضعیت Network Interfaceهای سیستم است.

Terminal 
ip addr

این دستور Interfaceها، IP Addressها و وضعیت آن‌ها را نمایش می‌دهد.

برای مشاهده Interfaceها می‌توانیم از این دستور نیز استفاده کنیم:

Terminal 
ip link

اگر Interface موردنظر DOWN باشد، ممکن است ارتباط شبکه برقرار نشود.

بررسی ارتباط با ping

یکی از ساده‌ترین ابزارهای Troubleshooting، دستور ping است.

ping با ارسال ICMP Echo Request بررسی می‌کند که آیا مقصد می‌تواند پاسخ دهد یا خیر.

Terminal 
ping 8.8.8.8

اگر پاسخ‌هایی مانند زیر دریافت کنیم، یعنی سیستم توانسته با مقصد ارتباط برقرار کند:

Example 
64 bytes from 8.8.8.8: icmp_seq=1 ttl=117 time=25.3 ms

برای توقف ping می‌توانیم از Ctrl + C استفاده کنیم.

⚠️ عدم پاسخ Ping همیشه به معنی قطع بودن شبکه نیست. ممکن است مقصد یا Firewall، ترافیک ICMP را مسدود کرده باشد.

بررسی Routing

اگر سیستم IP داشته باشد ولی نتواند به شبکه‌های دیگر دسترسی پیدا کند، باید Routing Table را بررسی کنیم.

Terminal 
ip route

معمولاً باید یک Default Route داشته باشیم که مسیر خروجی سیستم به شبکه‌های دیگر را مشخص می‌کند.

Example 
default via 192.168.1.1 dev ens33

در این مثال Gateway سیستم 192.168.1.1 است.

بررسی DNS

ممکن است اینترنت و ارتباط IP کاملاً سالم باشند اما Domain Nameها Resolve نشوند.

برای مثال:

Terminal 
ping google.com

اگر ping به IP کار کند ولی Domain کار نکند، یکی از مواردی که باید بررسی کنیم DNS است.

برای بررسی DNS می‌توانیم از ابزارهایی مانند resolvectl یا dig استفاده کنیم.

Terminal 
resolvectl status
Terminal 
dig google.com

بررسی Portها با ss

بعد از اینکه مطمئن شدیم Network درست کار می‌کند، باید بررسی کنیم سرویس موردنظر روی Port موردنیاز در حال Listen کردن هست یا خیر.

ابزار ss یکی از ابزارهای مهم Linux برای مشاهده Socketها و Connectionهاست.

Terminal 
ss -tuln

گزینه‌های مهم:

  • -t → TCP
  • -u → UDP
  • -l → Listening
  • -n → نمایش عددی IP و Port

مثلاً برای بررسی Port 80:

Terminal 
ss -tuln | grep :80

تست سرویس HTTP با curl

اگر یک Web Server یا API داریم، بهتر است خود Application Layer را نیز تست کنیم.

Terminal 
curl http://localhost

برای مشاهده Headerهای HTTP:

Terminal 
curl -I http://localhost

این روش بسیار مفید است چون به ما نشان می‌دهد آیا Web Server واقعاً پاسخ HTTP می‌دهد یا خیر.

بررسی مسیر Packet با traceroute

گاهی مقصد قابل دسترسی نیست و می‌خواهیم بدانیم Packetها در کدام قسمت مسیر دچار مشکل می‌شوند.

برای این کار می‌توانیم از traceroute استفاده کنیم.

Ubuntu 
sudo apt install traceroute

traceroute 8.8.8.8

خروجی traceroute معمولاً Hopهای مختلف بین سیستم شما و مقصد را نشان می‌دهد.

بررسی Packetها با tcpdump

گاهی Commandهای معمولی کافی نیستند و باید واقعاً ببینیم چه Packetهایی روی Interface رد و بدل می‌شوند.

در این شرایط ابزار قدرتمند tcpdump استفاده می‌شود.

Terminal 
sudo tcpdump -i any

برای مشاهده Traffic مربوط به یک Port خاص:

Terminal 
sudo tcpdump -i any port 80

برای توقف tcpdump از Ctrl + C استفاده کن.

⚠️ tcpdump می‌تواند حجم زیادی از اطلاعات شبکه را نمایش دهد. در محیط Production بهتر است Capture را با Filter مناسب انجام دهیم.

🧪 تمرین

روی Ubuntu این مراحل را به ترتیب انجام بده:

Ubuntu Terminal 
# 1. مشاهده Interfaceها
ip addr

# 2. مشاهده Routing
ip route

# 3. تست Gateway
ping -c 4 192.168.1.1

# 4. تست یک IP خارجی
ping -c 4 8.8.8.8

# 5. تست DNS
ping -c 4 google.com

# 6. مشاهده Portهای Listening
ss -tuln

# 7. تست HTTP
curl -I https://example.com

# 8. مشاهده مسیر
traceroute 8.8.8.8

هدف تمرین این است که به جای اجرای تصادفی Commandها، یک روش مرحله‌به‌مرحله برای پیدا کردن مشکل شبکه داشته باشی.

Network Troubleshooting Cheat Sheet

Command کاربرد
ip addr مشاهده IP و Interfaceها
ip link مشاهده وضعیت Interface
ip route مشاهده Routing Table
ping تست ارتباط شبکه
ss -tuln مشاهده Portهای Listening
curl تست HTTP و API
traceroute بررسی مسیر Packet
tcpdump Capture و بررسی Packetها
dig بررسی DNS

چیزی که از این مرحله یاد گرفتم

  • قبل از بررسی Application باید وضعیت Network را بررسی کنم.
  • با ip addr می‌توانم IP و Interfaceها را بررسی کنم.
  • با ip route مسیرهای سیستم را بررسی می‌کنم.
  • با ping ارتباط پایه را تست می‌کنم.
  • با ss وضعیت Portها و Connectionها را بررسی می‌کنم.
  • با curl خود سرویس HTTP را تست می‌کنم.
  • با traceroute مسیر Packetها را بررسی می‌کنم.
  • با tcpdump می‌توانم Packetهای واقعی شبکه را مشاهده کنم.
