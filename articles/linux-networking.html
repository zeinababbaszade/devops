چرا Networking برای DevOps مهم است؟

تقریباً هر سرویس DevOps به شبکه وابسته است. Client باید به Server وصل شود، سرویس‌ها باید روی Portهای مشخص Listen کنند و DNS باید نام‌ها را به IP تبدیل کند. بنابراین قبل از Docker و Kubernetes باید مفاهیم پایه Networking را خوب بشناسیم.

💡 هدف این مقاله Networking پیشرفته نیست؛ می‌خواهیم ابزارهای پایه‌ای را روی Ubuntu اجرا کنیم و بفهمیم سیستم چه Interfaceها، IPها، Routeها و Connectionهایی دارد.

IP و Interface

برای دیدن Interfaceهای شبکه و IPهای آن‌ها از دستور ip استفاده می‌کنیم.

Terminal
ip addr

خلاصه‌تر:

Terminal
ip -br addr

Routing

سیستم باید بداند برای رسیدن به شبکه‌های مختلف بسته‌ها را از چه مسیری ارسال کند. جدول Route را می‌توان با دستور زیر دید.

Terminal
ip route
💡 اگر Default Route وجود داشته باشد، معمولاً برای مقصدهایی که Route مشخص دیگری ندارند استفاده می‌شود.

بررسی Connectivity با ping

دستور ping برای آزمایش دسترسی شبکه به یک مقصد و اندازه‌گیری زمان پاسخ استفاده می‌شود.

Terminal
ping -c 4 8.8.8.8

اگر IP کار کرد اما یک نام دامنه کار نکرد، احتمالاً باید DNS را هم بررسی کنیم؛ البته علت می‌تواند موارد دیگری هم باشد.

DNS

DNS نام‌هایی مثل example.com را به اطلاعاتی مانند IP تبدیل می‌کند. برای یک تست ساده می‌توان از ابزارهایی مثل getent استفاده کرد.

Terminal
getent hosts example.com

همچنین در سیستم‌های دارای ابزار مناسب می‌توان از dig استفاده کرد.

Terminal
dig example.com

Port چیست؟

IP مشخص می‌کند به کدام Host می‌خواهیم برسیم و Port کمک می‌کند مشخص شود با کدام سرویس یا Endpoint ارتباط داریم. برای مثال Web Serverها معمولاً روی Portهای مشخصی Listen می‌کنند.

برای دیدن Socketها و Portهای Listening:

Terminal
ss -tuln

Connectionهای فعال

برای مشاهده Connectionهای TCP می‌توان از:

Terminal
ss -tn

استفاده کرد. این دستور برای Troubleshooting شبکه بسیار کاربردی است.

تست HTTP با curl

برای بررسی یک HTTP Endpoint می‌توان از curl استفاده کرد.

Terminal
curl -I https://example.com

این روش کمک می‌کند بفهمیم درخواست HTTP تا چه حد به مقصد می‌رسد و چه Status Codeای برمی‌گردد.

تمرین عملی: Networking Lab

🧪 تمرین

Ubuntu Terminal

خروجی هر دستور را نگاه کن و برای خودت به این سؤال‌ها جواب بده: IP سیستم چیست؟ Default Route چیست؟ DNS چه IPای برگرداند؟ چه Portهایی در حال Listen هستند؟

یک روش ساده برای Troubleshooting شبکه

وقتی یک سرویس به مقصدی دسترسی ندارد، بهتر است مرحله‌به‌مرحله جلو برویم و همه چیز را یک‌جا مقصر ندانیم.

  1. Interface و IP را بررسی کن.
  2. Route را بررسی کن.
  3. Connectivity پایه را تست کن.
  4. DNS را جداگانه بررسی کن.
  5. Port و Listening Service را بررسی کن.
  6. در نهایت خود Application را بررسی کن.

Networking Cheat Sheet

Commandکاربرد
ip addrنمایش Interface و IP
ip -br addrنمایش خلاصه IPها
ip routeنمایش Routing Table
ping -c 4 hostتست Connectivity
getent hosts hostبررسی Resolution نام
ss -tulnنمایش Portهای Listening
ss -tnنمایش TCP Connectionها
curl -I URLتست HTTP و Headerها
dig domainبررسی DNS با ابزار dig

چیزی که از این مرحله یاد گرفتم

  • با ip می‌توانم Interface، IP و Route را بررسی کنم.
  • با ping Connectivity را آزمایش می‌کنم.
  • DNS را باید از Connectivity جداگانه بررسی کنم.
  • با ss می‌توانم Portها و Connectionها را ببینم.
  • curl برای تست HTTP Endpointها بسیار کاربردی است.

مرحله بعدی چیست؟

🔐 SSH

در مقاله بعدی سراغ SSH می‌روم؛ یعنی اتصال امن به Linux Server، ساخت و استفاده از SSH Key، تنظیمات پایه و نکات امنیتی مهم.
