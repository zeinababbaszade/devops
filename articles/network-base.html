شبکه چیست؟

شبکه یا Network مجموعه‌ای از سیستم‌ها، تجهیزات و سرویس‌هایی است که برای انتقال اطلاعات با یکدیگر ارتباط برقرار می‌کنند. این سیستم‌ها می‌توانند کامپیوتر، Server، Router، Switch، Firewall، Container یا حتی یک Virtual Machine باشند.

در مسیر DevOps، شبکه یکی از پایه‌ای‌ترین مفاهیمی است که باید به‌خوبی یاد بگیریم. تقریباً هر سرویس DevOps به نوعی با Network سروکار دارد؛ از SSH و Web Server گرفته تا Docker، Kubernetes، Zabbix، Grafana، Database و Cloud.

💡 اگر یک Application بالا باشد ولی Network بین Client و Server درست کار نکند، از دید کاربر آن Application عملاً در دسترس نیست. بنابراین یک DevOps Engineer باید بتواند مشکل Network را مرحله‌به‌مرحله بررسی کند.

Network Interface چیست؟

برای اینکه یک Linux Server بتواند با شبکه ارتباط برقرار کند، به یک Network Interface نیاز دارد. این Interface می‌تواند یک کارت شبکه فیزیکی یا یک Interface مجازی باشد.

در یک Server ممکن است Interfaceهایی مانند eth0، ens33، ens160 یا نام‌های مشابه ببینیم. نام Interface به تنظیمات سیستم‌عامل و نوع سخت‌افزار یا Virtualization بستگی دارد.

برای مشاهده Interfaceهای سیستم:

Ubuntu Terminal 
ip link

برای مشاهده اطلاعات کامل‌تر Interfaceها و IP:

Ubuntu Terminal 
ip addr

در خروجی ممکن است چیزی شبیه این ببینیم:

Example 
2: ens160:
    inet 192.168.1.20/24
    link/ether 00:0c:29:12:34:56

در این مثال Interface ما ens160 است. این Interface دارای IP 192.168.1.20 و یک MAC Address است.

MAC Address چیست؟

هر Network Interface معمولاً یک شناسه سخت‌افزاری یا اصطلاحاً MAC Address دارد. MAC معمولاً به شکل شش گروه hexadecimal نمایش داده می‌شود.

Example 
00:0c:29:12:34:56

MAC Address در سطح Data Link برای شناسایی Interfaceها در شبکه‌های محلی استفاده می‌شود. در مقابل، IP Address برای ارتباط منطقی و مسیریابی بین شبکه‌ها استفاده می‌شود.

💡 یک راه ساده برای تفکیک ذهنی: MAC = شناسایی Interface در شبکه محلی و IP = آدرس منطقی برای ارتباط و Routing.

IP Address چیست؟

برای اینکه سیستم‌ها بتوانند یکدیگر را در شبکه پیدا کنند، از IP Address استفاده می‌شود.

در IPv4 یک Address از چهار بخش تشکیل می‌شود که با نقطه از هم جدا شده‌اند:

IPv4 Example 
192.168.1.20

هر بخش IPv4 می‌تواند مقداری بین 0 تا 255 داشته باشد. اما فقط دانستن IP کافی نیست؛ برای درک اینکه یک IP متعلق به چه Networkای است، باید Subnet Mask یا notation مربوط به آن را هم بدانیم.

مثلاً:

Example 
192.168.1.20/24

عدد /24 مشخص می‌کند چه تعداد بیت برای Network Portion در نظر گرفته شده است. مفهوم Subnet و CIDR را در مقاله بعدی به‌صورت کامل بررسی می‌کنیم.

Private و Public IP

همه IPها مستقیماً روی Internet قابل استفاده نیستند. بخشی از IPv4 Addressها برای شبکه‌های خصوصی در نظر گرفته شده‌اند.

Range کاربرد
10.0.0.0/8 Private Network
172.16.0.0/12 Private Network
192.168.0.0/16 Private Network

مثلاً IP زیر یک Private IP است:

Example 
192.168.1.20

سیستم‌های داخل شبکه داخلی می‌توانند از این IPها استفاده کنند، ولی برای ارتباط با Internet معمولاً به NAT و یک Public IP در سمت شبکه نیاز داریم.

Gateway چیست؟

فرض کن Server ما می‌خواهد با سیستمی در یک Network دیگر ارتباط برقرار کند. در این حالت معمولاً Packet باید به یک Router یا Gateway ارسال شود.

به زبان ساده: Gateway در بسیاری از شبکه‌ها مسیر خروج سیستم از Network محلی به شبکه‌های دیگر است.

برای مشاهده Gateway و Routeهای سیستم:

Ubuntu Terminal 
ip route

ممکن است خروجی شبیه این باشد:

Example 
default via 192.168.1.1 dev ens160
192.168.1.0/24 dev ens160 proto kernel scope link src 192.168.1.20

خط اول یعنی برای مقصدهایی که Route مشخص‌تری ندارند، سیستم Packet را به Gateway 192.168.1.1 ارسال می‌کند.

DNS چیست؟

DNS مخفف Domain Name System است. کار DNS تبدیل نام‌هایی مثل example.com به IP Address است.

کامپیوترها برای ارتباط شبکه‌ای به Address نیاز دارند، ولی انسان‌ها کار کردن با نام‌ها را راحت‌تر می‌دانند. DNS این فاصله را پر می‌کند.

مثلاً وقتی یک Application می‌خواهد به:

Example 
example.com

متصل شود، ابتدا باید مشخص شود این نام به چه IP Addressای اشاره می‌کند.

برای تست DNS در Linux می‌توانیم از ابزارهایی مانند dig استفاده کنیم.

Ubuntu Terminal 
dig example.com

یا:

Ubuntu Terminal 
nslookup example.com
⚠️ اگر IP را Ping کنیم و پاسخ بگیریم ولی نام Domain کار نکند، ممکن است مشکل از DNS باشد؛ بنابراین باید Network Connectivity و Name Resolution را جداگانه بررسی کنیم.

Route چیست؟

هر Linux Server یک Routing Table دارد که مشخص می‌کند Packetها برای رسیدن به مقصدهای مختلف از چه مسیری ارسال شوند.

برای مشاهده Routing Table:

Ubuntu Terminal 
ip route

یک Route معمولاً مشخص می‌کند:

  • Destination Network
  • Gateway
  • Network Interface
  • Source Address

مثلاً:

Example 
default via 192.168.1.1 dev ens160

یعنی Route پیش‌فرض از Gateway 192.168.1.1 و Interface ens160 استفاده می‌کند.

دستورات مهم Networking

Command کاربرد
ip addr مشاهده IP و Interfaceها
ip link مشاهده وضعیت Interfaceها
ip route مشاهده Routing Table
ping بررسی Connectivity
ss بررسی Socketها و Connectionها
dig بررسی DNS
curl تست HTTP و سرویس‌ها
ip neigh مشاهده Neighbor/ARP information

تست ارتباط با ping

یکی از ساده‌ترین ابزارهای بررسی Network، دستور ping است.

Ubuntu Terminal 
ping 8.8.8.8

اگر پاسخ دریافت شود، حداقل نشان می‌دهد که مسیر ارتباطی تا مقصد در سطحی از Network Connectivity برقرار است.

اما یک نکته بسیار مهم وجود دارد: موفق بودن ping به معنی سالم بودن تمام سرویس‌های مقصد نیست.

مثلاً ممکن است Web Server روی Port 443 مشکل داشته باشد ولی ICMP و در نتیجه ping همچنان پاسخ بدهد.

برای تست یک Host با تعداد محدود Packet:

Ubuntu Terminal 
ping -c 4 8.8.8.8

بررسی Connectionها با ss

ابزار ss برای مشاهده Socketها و Connectionهای شبکه در Linux بسیار کاربردی است.

برای مشاهده Connectionهای TCP:

Ubuntu Terminal 
ss -t

برای مشاهده Listening Portها:

Ubuntu Terminal 
ss -lnt

برای دیدن Process مرتبط با Socketها نیز می‌توان از:

Ubuntu Terminal 
sudo ss -lntp

این دستور برای Troubleshooting بسیار مفید است. مثلاً اگر انتظار داریم یک Web Server روی Port 8080 گوش دهد، می‌توانیم بررسی کنیم آیا واقعاً Port موردنظر Listening است یا خیر.

روش Troubleshooting شبکه

یکی از مهم‌ترین مهارت‌ها در DevOps این نیست که صدها Command را حفظ کنیم؛ بلکه باید بتوانیم مشکل را مرحله‌به‌مرحله محدود کنیم.

فرض کنیم Server به Internet دسترسی ندارد. نباید بلافاصله سراغ DNS برویم. ابتدا باید مشخص کنیم مشکل دقیقاً در کدام لایه قرار دارد.

مرحله 1 — Interface

Terminal 
ip link

بررسی می‌کنیم Interface موردنظر فعال است یا خیر.

مرحله 2 — IP Address

Terminal 
ip addr

بررسی می‌کنیم Server یک IP مناسب دارد یا خیر.

مرحله 3 — Routing

Terminal 
ip route

بررسی می‌کنیم Default Route وجود دارد یا خیر.

مرحله 4 — Gateway

Terminal 
ping -c 4 192.168.1.1

اگر Gateway قابل دسترسی نباشد، باید قبل از بررسی Internet مشکل شبکه محلی را بررسی کنیم.

مرحله 5 — IP خارجی

Terminal 
ping -c 4 8.8.8.8

اگر Gateway پاسخ می‌دهد ولی IP خارجی نه، مشکل می‌تواند در Routing، Firewall، NAT یا مسیر بالادستی باشد.

مرحله 6 — DNS

Terminal 
ping -c 4 example.com

اگر IP خارجی کار می‌کند ولی Domain نه، DNS را بررسی می‌کنیم.

روی Ubuntu خودت دستورات زیر را به ترتیب اجرا کن:

Ubuntu Terminal 
ip link

ping -c 4 127.0.0.1

برای هر دستور سعی کن قبل از اجرای آن حدس بزنی چه اطلاعاتی قرار است ببینی.

بعد از اجرای دستورات، این موارد را برای خودت یادداشت کن:

  • نام Network Interface
  • IPv4 Address
  • Subnet/CIDR
  • Default Gateway
  • DNS Server
  • Listening Ports

چیزی که از این مرحله یاد گرفتم

  • Network Interface نقطه اتصال Linux به شبکه است.
  • هر Interface می‌تواند IP و MAC Address داشته باشد.
  • IP برای Addressing و ارتباط منطقی استفاده می‌شود.
  • Gateway برای رسیدن به شبکه‌های دیگر اهمیت دارد.
  • Routing Table مشخص می‌کند Packetها به کجا ارسال شوند.
  • DNS نام Domain را به IP تبدیل می‌کند.
  • Ping برای بررسی Connectivity مفید است ولی سلامت یک سرویس را به‌تنهایی ثابت نمی‌کند.
  • با ss می‌توان Listening Portها و Connectionها را بررسی کرد.
  • در Troubleshooting باید مشکل را مرحله‌به‌مرحله محدود کنیم.
