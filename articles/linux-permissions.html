مجوزها و Permissionها در Linux

آشنایی با Owner، Group، Read، Write، Execute و دستورهای chmod و chown.

مقدمه

Linux یک سیستم‌عامل چندکاربره است و کاربران مختلف می‌توانند روی یک سیستم کار کنند.

بنابراین Linux باید مشخص کند چه کسی اجازه دارد یک فایل را بخواند، تغییر دهد یا اجرا کند.

این کنترل دسترسی با استفاده از File Permissions انجام می‌شود.

1. مشاهده Permissionها

برای مشاهده Permission و مالکیت فایل‌ها می‌توانیم از دستور زیر استفاده کنیم: 

ls -l

ممکن است خروجی چیزی شبیه این باشد: 

-rw-r--r-- 1 user user 120 Sep 7 10:00 notes.txt

قسمت ابتدایی یعنی: 

-rw-r--r--

Permissionهای فایل را مشخص می‌کند.

2. مفهوم r ،w و x

حرف معنی
r Read - خواندن
w Write - نوشتن
x Execute - اجرا

این Permissionها برای سه گروه اصلی تعریف می‌شوند:

  • Owner — مالک فایل
  • Group — گروه فایل
  • Others — سایر کاربران

بنابراین اگر Permission به شکل زیر باشد: 

-rwxr-xr--

می‌توانیم آن را به این شکل تقسیم کنیم: 

Owner     Group     Others
rwx       r-x       r--

3. Permissionهای عددی

در Linux می‌توان Permissionها را با اعداد نیز مشخص کرد.

Permission مقدار
Read (r) 4
Write (w) 2
Execute (x) 1

بنابراین: 

rwx = 4 + 2 + 1 = 7

rw- = 4 + 2 = 6

r-x = 4 + 1 = 5

r-- = 4

مثلاً Permission زیر: 

755

یعنی: 

Owner  = 7 = rwx
Group  = 5 = r-x
Others = 5 = r-x

4. تغییر Permission با chmod

برای تغییر Permission فایل‌ها از دستور chmod استفاده می‌کنیم.

برای مثال: 

chmod 755 script.sh

یا: 

chmod 644 notes.txt

Permission 644 یعنی: 

Owner  = rw-
Group  = r--
Others = r--

5. تغییر Permission به روش Symbolic

علاوه بر روش عددی، می‌توانیم Permission را به شکل Symbolic نیز تغییر دهیم.

برای اضافه کردن Execute به Owner: 

chmod u+x script.sh

برای حذف Write از Others: 

chmod o-w notes.txt

برای اضافه کردن Write به Group: 

chmod g+w notes.txt

حروف مهم: 

u = Owner
g = Group
o = Others
a = All

6. مالکیت فایل و chown

فایل‌ها در Linux علاوه بر Permission، دارای Owner و Group نیز هستند.

برای مشاهده آن‌ها: 

ls -l

برای تغییر Owner می‌توان از chown استفاده کرد: 

sudo chown username file.txt

برای تغییر Owner و Group: 

sudo chown username:groupname file.txt
هشدار:

هنگام استفاده از sudo chown روی فایل‌های سیستمی بسیار دقت کنید.

7. تمرین عملی

حالا یک محیط آزمایشی برای Permissionها ایجاد می‌کنیم.

مرحله اول — ساخت دایرکتوری

cd ~

mkdir -p devops-lab/permissions

cd ~/devops-lab/permissions

مرحله دوم — ساخت فایل

echo "Linux Permissions Lab" > notes.txt

مرحله سوم — مشاهده Permission

ls -l notes.txt

مرحله چهارم — تغییر Permission

chmod 600 notes.txt

ls -l notes.txt

سپس Permission را به حالت دیگری تغییر می‌دهیم: 

chmod 644 notes.txt

ls -l notes.txt

مرحله پنجم — ساخت یک Script

echo '#!/bin/bash' > hello.sh

echo 'echo "Hello from Linux"' >> hello.sh

مرحله ششم — اجرای Script

./hello.sh

اگر Execute Permission نداشته باشد، ممکن است با خطای Permission Denied مواجه شوید.

مرحله هفتم — اضافه کردن Execute

chmod u+x hello.sh

حالا دوباره اجرا کنید: 

./hello.sh
تمرین پیشنهادی:

Permissionهای فایل hello.sh را با ls -l بررسی کن و ببین بعد از اجرای chmod u+x چه تغییری در Permission ایجاد شده است.

8. چرا Permissionها در DevOps مهم هستند؟

Permissionها یکی از مفاهیم بسیار مهم در مدیریت Serverهای Linux هستند.

اگر Permissionها اشتباه تنظیم شوند، ممکن است باعث مشکلات امنیتی یا خطاهای Application شوند.

برای مثال:

  • کاربر غیرمجاز بتواند فایل را تغییر دهد.
  • یک Application نتواند فایل موردنیاز خود را بخواند.
  • یک Script اجازه اجرا نداشته باشد.
  • یک سرویس به فایل Configuration دسترسی نداشته باشد.

در DevOps باید تا حد امکان فقط Permissionهای موردنیاز را به کاربران و سرویس‌ها بدهیم.
