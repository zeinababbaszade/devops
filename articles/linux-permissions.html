Permission در Linux چیست؟

در Linux فقط داشتن یک فایل کافی نیست؛ سیستم باید بداند چه کسی اجازه دارد آن را بخواند، تغییر دهد یا اجرا کند. این موضوع برای امنیت سرورها و سرویس‌های DevOps بسیار مهم است.

💡 سه سطح اصلی دسترسی عبارت‌اند از Owner، Group و Others و سه Permission اصلی هم Read، Write و Execute هستند.

دیدن Permissionها با ls -l

Terminal
ls -l

ممکن است خروجی چیزی شبیه این باشد:

Output
-rw-r--r-- 1 user user 120 Sep 7 10:00 notes.txt

بخش -rw-r--r-- اطلاعات Permission فایل را نشان می‌دهد.

Read، Write و Execute

Permissionنمادمفهوم
Readrخواندن
Writewنوشتن یا تغییر
Executexاجرا کردن
هیچ دسترسی-بدون Permission مربوطه

سه کاراکتر اول بعد از نوع فایل برای Owner، سه کاراکتر بعدی برای Group و سه کاراکتر آخر برای Others هستند.

Permissionهای عددی

برای استفاده عددی، مقدار هر Permission این است:

PermissionValue
Read4
Write2
Execute1

بنابراین 7 = 4+2+1 یعنی Read + Write + Execute و 6 = 4+2 یعنی Read + Write.

تغییر Permission با chmod

برای تغییر Permission از chmod استفاده می‌کنیم.

Terminal
chmod 644 notes.txt
chmod 755 script.sh

در 644، Owner دسترسی Read/Write دارد و Group و Others فقط Read دارند. در 755، Owner هر سه دسترسی و Group و Others معمولاً Read و Execute دارند.

روش Symbolic

Terminal
chmod u+x script.sh
chmod g+w notes.txt
chmod o-w notes.txt

u یعنی User/Owner، g یعنی Group و o یعنی Others.

تغییر Owner با chown

دستور chown برای تغییر مالک فایل یا Directory استفاده می‌شود.

Terminal
sudo chown labuser notes.txt

برای تغییر Owner و Group می‌توان از ساختار زیر استفاده کرد:

Terminal
sudo chown labuser:devops-lab notes.txt

Permission برای Scriptها

یک فایل Shell Script تا زمانی که Execute Permission مناسب نداشته باشد، لزوماً به شکل مستقیم قابل اجرا نیست.

Terminal
touch hello.sh
echo '#!/bin/bash' > hello.sh
echo 'echo "Hello DevOps"' >> hello.sh
chmod +x hello.sh
./hello.sh

تمرین عملی: Permission Lab

🧪 تمرین

دستورات زیر را روی Ubuntu اجرا کن:

Ubuntu Terminal
cd ~/devops-lab
mkdir -p linux/permissions
cd linux/permissions
touch notes.txt
chmod 644 notes.txt
ls -l notes.txt
touch deploy.sh
echo '#!/bin/bash' > deploy.sh
echo 'echo "Deployment test"' >> deploy.sh
chmod 755 deploy.sh
ls -l deploy.sh
./deploy.sh

قبل و بعد از chmod خروجی ls -l را مقایسه کن.

چرا Permissionها برای DevOps مهم هستند؟

روی یک سرور واقعی، همه کاربران و سرویس‌ها نباید به همه فایل‌ها دسترسی داشته باشند. محدود کردن دسترسی باعث کاهش ریسک تغییر یا مشاهده ناخواسته فایل‌های مهم می‌شود.

⚠️ اجرای دستورهایی مثل chmod -R 777 معمولاً راه‌حل مناسبی برای خطای Permission نیست. قبل از باز کردن دسترسی‌ها، Owner، Group و Permission فعلی را بررسی کن.

Permission Cheat Sheet

Commandکاربرد
ls -lمشاهده Permissionها و Owner
chmod 644 fileتنظیم Permission عددی
chmod +x fileافزودن Execute
chmod u+x fileافزودن Execute برای Owner
chown user fileتغییر Owner
chown user:group fileتغییر Owner و Group

چیزی که از این مرحله یاد گرفتم

  • Permissionها به Owner، Group و Others تقسیم می‌شوند.
  • r، w و x به ترتیب Read، Write و Execute هستند.
  • با chmod می‌توان Permission را تغییر داد.
  • با chown می‌توان مالکیت فایل را تغییر داد.
  • Permission مناسب یکی از پایه‌های امنیت Linux است.
