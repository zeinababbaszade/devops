Linux Permissions

Understanding Linux file permissions, chmod, chown and access control.

Introduction

Linux is a multi-user operating system. Multiple users and services can work on the same system.

Because of this, Linux needs a mechanism to control who can read, modify or execute files.

This mechanism is called File Permissions.

1. Reading File Permissions

We can use ls -l to see file permissions. 

ls -l

A result might look like: 

-rw-r--r-- 1 user user 120 Sep 7 10:00 notes.txt

The first part: 

-rw-r--r--

contains the permission information.

2. Understanding rwx

Linux permissions are based on three basic permissions:

Symbol Meaning
r Read
w Write
x Execute

These permissions are applied to three categories:

  • Owner
  • Group
  • Others

Therefore a permission such as: 

-rwxr-xr--

can be divided like this: 

Owner   Group   Others
rwx     r-x     r--

3. Numeric Permissions

Linux also allows us to represent permissions using numbers.

Permission Value
Read (r) 4
Write (w) 2
Execute (x) 1

For example: 

rwx = 4 + 2 + 1 = 7
rw- = 4 + 2 = 6
r-x = 4 + 1 = 5
r-- = 4

Therefore: 

755

means: 

Owner   = 7 = rwx
Group   = 5 = r-x
Others  = 5 = r-x

4. chmod

The chmod command changes file permissions.

For example: 

chmod 755 script.sh

This gives the owner full permissions and gives read and execute permissions to the group and others.

Another common example: 

chmod 644 notes.txt

This means: 

Owner   = rw-
Group   = r--
Others  = r--

5. Symbolic chmod

Permissions can also be changed using symbolic notation.

Give the owner execute permission: 

chmod u+x script.sh

Remove write permission from others: 

chmod o-w notes.txt

Give the group write permission: 

chmod g+w project.txt

The letters mean: 

u = user / owner
g = group
o = others
a = all

6. File Ownership

Linux files also have an owner and a group.

We can inspect ownership using: 

ls -l

The chown command changes ownership. 

sudo chown username file.txt

We can change both owner and group: 

sudo chown username:groupname file.txt
Important:

Be careful when using sudo chown on system files.

7. Practical Lab

Let's create a small permission lab.

Step 1 — Create the directory

cd ~

mkdir -p devops-lab/permissions

cd ~/devops-lab/permissions

Step 2 — Create a file

echo "Linux Permissions Lab" > notes.txt

Step 3 — Check permissions

ls -l notes.txt

Step 4 — Change permissions

chmod 600 notes.txt

Check again: 

ls -l notes.txt

Now try: 

chmod 644 notes.txt

ls -l notes.txt

Step 5 — Create a script

echo '#!/bin/bash' > hello.sh
echo 'echo "Hello from Linux"' >> hello.sh

Step 6 — Try to execute it

./hello.sh

Depending on the current permissions, you may receive a permission denied error.

Step 7 — Add execute permission

chmod u+x hello.sh

Now run: 

./hello.sh

The script should now execute.

8. Why Permissions Matter in DevOps

File permissions are extremely important in DevOps.

Applications, services and users should only have the permissions they actually need.

Incorrect permissions can cause:

  • Security vulnerabilities
  • Application failures
  • Permission denied errors
  • Unauthorized access

Understanding permissions will become especially important when working with SSH, Docker, web servers and CI/CD pipelines.

Command Purpose

chmod Change permissions
chown Change owner
