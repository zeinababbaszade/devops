Port چیست؟

در شبکه، یک سیستم می‌تواند هم‌زمان چندین سرویس مختلف ارائه کند.

مثلاً ممکن است روی یک Server هم‌زمان Web Server، SSH، Database و Monitoring Agent اجرا شوند.

اگر فقط IP Address داشته باشیم، مشخص نیست Packet باید به کدام سرویس تحویل داده شود.

اینجاست که مفهوم Port مطرح می‌شود.

Port یک عدد بین 0 تا 65535 است که در پروتکل‌هایی مانند TCP و UDP برای مشخص کردن Endpoint یک سرویس استفاده می‌شود.

💡 می‌توان Port را مانند شماره یک اتاق در یک ساختمان در نظر گرفت. IP آدرس ساختمان است و Port مشخص می‌کند Packet باید به کدام سرویس برسد.

IP و Port چه تفاوتی دارند؟

IP Address یک سیستم را در شبکه مشخص می‌کند؛ اما Port مشخص می‌کند ارتباط مربوط به کدام سرویس است.

مثلاً:

Example 
192.168.1.10:22

در این مثال:

  • 192.168.1.10 → IP Address
  • 22 → Port

Port 22 معمولاً برای SSH استفاده می‌شود.

Socket چیست؟

Socket یکی از مفاهیم مهم Networking است.

به‌صورت ساده می‌توان گفت Socket یک Endpoint برای ارتباط شبکه‌ای است.

یک ارتباط معمولاً با اطلاعاتی مانند IP، Port و Protocol مشخص می‌شود.

مثلاً:

Example 
TCP 192.168.1.10:443

این اطلاعات مشخص می‌کنند که ارتباط TCP مربوط به IP و Port خاصی است.

TCP و Port

TCP یک پروتکل Connection-Oriented است.

قبل از انتقال داده، TCP یک Connection بین دو طرف ایجاد می‌کند.

به همین دلیل در Troubleshooting سرویس‌های TCP، وضعیت Connection اهمیت زیادی دارد.

مثلاً HTTPS معمولاً روی Port 443 اجرا می‌شود.

Example 
TCP 443

UDP و Port

UDP برخلاف TCP Connection-Oriented نیست و سربار کمتری دارد.

UDP در سرویس‌هایی که سرعت و سادگی مهم هستند کاربرد زیادی دارد.

DNS، DHCP و برخی سرویس‌های Monitoring می‌توانند از UDP استفاده کنند.

💡 TCP و UDP هر دو از Port Number استفاده می‌کنند، اما نحوه مدیریت ارتباط در آن‌ها متفاوت است.

Well-Known Ports

برخی Portها به‌صورت استاندارد برای سرویس‌های شناخته‌شده استفاده می‌شوند.

Port Service
22 SSH
53 DNS
80 HTTP
123 NTP
443 HTTPS
3306 MySQL
5432 PostgreSQL
6379 Redis
⚠️ شماره Port به‌تنهایی تضمین نمی‌کند چه سرویسی روی آن اجرا می‌شود. یک Administrator می‌تواند سرویس را روی Port دیگری اجرا کند.

Listening Port چیست؟

وقتی یک Server منتظر Connectionهای جدید روی یک Port باشد، می‌گوییم روی آن Port در وضعیت LISTEN قرار دارد.

مثلاً اگر SSH روی Port 22 فعال باشد، می‌توانیم چیزی شبیه این مشاهده کنیم:

Example 
LISTEN 0 128 0.0.0.0:22

یعنی یک سرویس در حال Listen کردن روی Port 22 است.

بررسی Portها با ss

در Linux امروزی، ابزار ss یکی از ابزارهای اصلی برای مشاهده Socketها و Connectionهاست.

Terminal 
ss -tuln

برای مشاهده Connectionهای TCP:

Terminal 
ss -tn

برای مشاهده Connectionهای Listening:

Terminal 
ss -ltn

پیدا کردن Process مربوط به Port

گاهی می‌دانیم Port مثلاً 8080 باز است اما نمی‌دانیم کدام Process از آن استفاده می‌کند.

با گزینه -p می‌توان اطلاعات Process را نیز مشاهده کرد.

Terminal 
sudo ss -ltnp

برای جستجوی یک Port خاص:

Terminal 
sudo ss -ltnp | grep :8080
💡 این روش برای زمانی که یک Application اجرا نمی‌شود و احتمال می‌دهیم Port موردنظر قبلاً توسط Process دیگری اشغال شده باشد بسیار کاربردی است.

تفاوت localhost و 0.0.0.0

یکی از مفاهیم مهم در Serverها، تفاوت بین 127.0.0.1 و 0.0.0.0 است.

127.0.0.1

این Address به Loopback Interface اشاره می‌کند و معمولاً فقط از خود همان سیستم قابل دسترسی است.

Example 
127.0.0.1:8080

0.0.0.0

اگر یک سرویس روی 0.0.0.0 Listen کند، در IPv4 معمولاً یعنی روی تمام IPv4 Interfaceهای سیستم Listen می‌کند.

Example 
0.0.0.0:8080
⚠️ Listen کردن روی همه Interfaceها می‌تواند سرویس را از شبکه‌های بیشتری قابل دسترسی کند. در محیط Production باید Access Control و Firewall را جدی بگیریم.

Port و Firewall

باز بودن یک Port در سیستم به این معنی نیست که حتماً از بیرون قابل دسترسی است.

Firewall می‌تواند Connectionهای ورودی را مسدود کند.

در Ubuntu ممکن است با UFW کار کنیم.

Ubuntu 
sudo ufw status

برای مشاهده Ruleهای Firewall:

Ubuntu 
sudo ufw status verbose
💡 برای Troubleshooting باید تفاوت بین «سرویس روی Port Listen می‌کند» و «Port از شبکه قابل دسترسی است» را درک کنیم. این دو یک چیز نیستند.

تمرین عملی: Port Lab

🧪 تمرین

در Ubuntu ابتدا یک Web Server ساده اجرا کن.

Ubuntu Terminal 
python3 -m http.server 8080

حالا Terminal دیگری باز کن و Port را بررسی کن:

Ubuntu Terminal 
ss -ltnp | grep :8080

سپس سرویس را با curl تست کن:

Ubuntu Terminal 
curl http://127.0.0.1:8080

حالا Process مربوط به Server را متوقف کن.

برای این کار می‌توانی در Terminal اول Ctrl + C بزنید.

دوباره Port را بررسی کن:

Ubuntu Terminal 
ss -ltnp | grep :8080

اگر خروجی‌ای مشاهده نشود، یعنی دیگر Process روی Port 8080 در حال Listen نیست.

Linux Ports Cheat Sheet

Command کاربرد
ss -tuln نمایش TCP/UDP Listening Portها
ss -ltn نمایش TCP Listening
ss -tn نمایش TCP Connectionها
sudo ss -ltnp نمایش Port به همراه Process
ip addr مشاهده IP Addressها
ip route مشاهده Routing
sudo ufw status بررسی وضعیت UFW
curl تست سرویس HTTP

چیزی که از این مرحله یاد گرفتم

  • Port مشخص می‌کند یک Connection مربوط به کدام سرویس است.
  • TCP و UDP از Port Number استفاده می‌کنند.
  • Socket یک Endpoint برای ارتباط شبکه‌ای است.
  • Listening یعنی یک سرویس منتظر Connectionهای ورودی است.
  • با ss می‌توان Portها و Connectionها را بررسی کرد.
  • با ss -p می‌توان Process مربوط به Port را پیدا کرد.
  • Listen بودن یک Port با قابل دسترس بودن آن از شبکه یکسان نیست.
  • Firewall می‌تواند دسترسی به Port را محدود کند.
